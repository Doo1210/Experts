# 专家任务：消息渠道对话与自主任务

状态：2026-10-28 原型需求整理。本文聚焦功能与数据规则；正式接入仍以 [专家总 PRD](./experts_prd.md) 及事件中心契约为准。

## 1. 对象与入口边界

专家管理页的「任务」包含平台对话、消息渠道对话、自主任务（事件中心）三个分区。三者不能共用一个任务或归档模型：

- **平台对话**对应用户在产品中发起的人工对话 session。
- **消息渠道对话卡片**对应当前专家在某渠道的一个聊天入口。一个卡片可包含多位群成员及多段内部 session；卡片 ID 不是 `session_id`。
- **自主任务卡片**对应事件中心绑定当前专家的一个稳定「专家执行动作」。每次事件命中动作形成独立的执行记录和 session；正式接入应以动作 ID＋专家 ID 归组，不能直接以整条事件或一次执行 ID 建卡。

消息渠道与自主任务由外部来源发起。前者在专家实际接收并保存首条有效对话后建卡，后续同一聊天继续归入该卡；仅启用渠道或配置机器人不建卡。后者在动作绑定后可以展示空记录卡，首次有效触发后必须出现或更新；事件被接收但未命中当前专家动作时不建卡。页面不提供创建渠道聊天或配置事件源的入口。

## 2. 消息渠道对话

### 2.1 卡片身份与来源

- 按专家/Profile、渠道、平台作用域和渠道原生聊天标识归组。同一群的多位成员只产生一张群聊卡；单聊按自身聊天标识建卡。
- 名称默认取渠道群名或单聊对象名。卡片展示渠道、群聊／单聊、最近活跃时间、原生标识和聊天工作目录；群聊最近活跃成员取最近一次专家已接收的用户消息发送者。最近活跃时间取最后一条已保存的用户或专家对话消息；无消息显示「暂无记录」。
- 标识由接入数据同时提供**字段名称和完整原值**。钉钉优先 `conversationId`，实际回退到 `senderId` 时标为 `senderId`；飞书使用 `chat_id`；企业微信群聊使用 `chatid`，单聊有 `chatid` 用它，否则按实际来源标为 `userid`。不得把成员身份 ID 冒充已有的聊天 ID，也不在卡片上展示内部 `session_id` 或 `session_key`。
- 支持名称或原生标识搜索，以及群聊／单聊、渠道筛选。对话任务数按当前筛选结果中的卡片数统计；运行中数按其中确认有 Hermes turn 正在执行的卡片数统计，同群多个运行 turn 仍只计一卡。状态未知不能当成 0 个运行中。运行图标只在确认运行中时显示。

### 2.2 为什么群聊按成员查看

群的原生聊天 ID 只标识**群位置**，不能代表每位成员与专家共享同一上下文。本期群聊的专家对话按发送成员建立独立的路由范围：不同成员可能提出无关问题、引用不同附件、拥有不同执行进度与工作目录。如果把全群消息合成一条历史，会把 A 成员的问题与 B 成员的回复或工具结果串在一起，也可能误导后续上下文读取。

因此群聊仍只有一张入口卡，但浮窗按**稳定成员标识**选择历史。成员列表只列确实与专家产生过记录的人，不等同于群通讯录；同名成员不得按显示名称合并。默认选最近活跃成员，支持按名称或成员标识搜索。右侧只读取该成员在当前专家、当前渠道、当前群中的记录，不混入其单聊、其他群或其他专家的记录。本期不提供「全部成员」或全群共享上下文；旧共享／线程记录不能强行归到某个人名下。

### 2.3 只读历史

- 单聊直接显示连续历史；群聊先选成员，再连续显示该成员的历史。底层多段 session 可用于读取和去重，但不向用户展示会话段列表、`/new`／`/reset` 操作或「已开启新对话」分隔。合并展示不改变当前模型上下文。
- 内容遵循[专家对话页 §5.3](./experts_conversation_prd.md#53-内容展示区)：用户输入及已发送资料、回合状态与可信用时、可折叠的已保存处理过程、最终回复和确认保存的产出。缺少可信状态或用时时不补造；工具过程默认折叠，产出文件按能力预览或下载。
- 问题定位条遵循[专家对话页 §5.4](./experts_conversation_prd.md#54-问题定位条)：每条用户提问对应一个定位项，支持预览对应最终回复、标记和跳转；标记按聊天及群成员保存。长记录先加载最新内容，向上加载更早记录并保持阅读位置，可回到最新。
- 用户输入气泡不重复显示成员名称，时间显示到年月日时分秒。浮窗没有输入区或会话状态操作区；不提供发送、审批、停止、重新执行。关闭浮窗不影响渠道路由或正在运行的任务。
- 工作目录入口独立于打开卡片。单聊打开聊天目录；群聊优先打开聊天级目录，仅有成员目录时要求选择。成员历史若涉及多个执行目录，可选择对应目录。删除历史不自动删除工作空间文件。

### 2.4 名称、归档、删除

卡片「更多」仅提供**编辑名称、归档、删除**。编辑保存的是独立显示名称，默认值为渠道原名称；弹窗同时展示原名称供参考，不修改平台名称、原生标识或回复路由。归档从当前列表隐藏卡片并保留历史，可从「归档 N」恢复；新有效入站对话出现时自动恢复。删除需确认，移除产品侧卡片和本地历史，工作空间文件保留；外部渠道以后再次产生有效对话时可以重新建卡。

## 3. 自主任务（事件中心）

### 3.1 卡片与统计

- 展示当前专家绑定的「专家执行动作」及其执行历史。卡片显示事件名称、触发源类型、来源摘要、最近一次执行时间和工作目录。来源类型包括 Timer、WebHook、Pulsar、Kafka、MQTT；摘要沿用事件中心实际配置，例如时间计划、主题或 WebHook 方法与路径。
- 支持按名称搜索及按触发源类型筛选，两个条件同时生效。任务总数和运行中数按未归档动作卡统计；一张卡只要存在确认运行中的执行记录即计为运行中，不能把「已启用」或「最近活跃」当成运行中。运行图标只在确认运行中时显示。
- 卡片点击后打开只读执行对话记录。每次触发记录输入快照、状态、已保存的处理过程、专家回复及产出；不同触发形成独立 session，不续接平台对话或消息渠道 session。工作目录建议为 `自主任务/<动作 ID>/runs/<执行 ID>/`，卡片目录停在动作级。

### 3.2 名称与生命周期

卡片「更多」仅提供**编辑名称、归档、删除**，不在此处编辑事件接入、处理分支、动作配置、启停或手动触发；这些由事件中心负责。显示名称默认取事件中心名称，编辑时保留原名称作参考，不能改变事件或动作身份。

归档隐藏卡片但保留执行历史，可从「归档 N」恢复；新执行到来时自动恢复。删除需确认，移除产品侧卡片和本地执行历史，事件中心来源与工作空间文件分别保留。若事件中心以后再次有效触发该专家动作，可重新建卡。删除一次执行 session 与删除动作卡不是同一操作。

## 4. 演示范围与正式接入待核对

当前工程仅使用浏览器本地数据，不调用消息渠道或事件中心 API。固定样例覆盖钉钉、飞书、企业微信的群聊与单聊，以及五类事件源；两类卡片均包含成功和确认运行中的记录，另外保留无记录、状态未知等场景。新增别名、归档和删除在本地保存，刷新后保持；重置演示数据可恢复固定样例。

正式接入前需对齐：

1. 消息渠道服务端返回聊天标识名称与原值、稳定成员身份、发送者、真实 turn 状态、历史消息及目录映射，并按 Profile／机器人／渠道隔离查询。
2. 事件中心返回稳定动作 ID、专家 ID、事件 ID、发布版本、分支、触发源摘要及每次执行 ID；产品按动作归卡，而不是依赖当前演示样例的事件 ID。
3. 删除与归档在真实服务端的权限、审计、历史保留和新活动自动恢复规则；工作空间文件清理须单独授权与定义，不能由删除卡片隐式执行。
