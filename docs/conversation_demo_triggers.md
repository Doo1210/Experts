# 专家对话原型演示触发词

本文集中记录**当前前端本地模拟器**的触发词与操作，依据 `src/demo/state.js` 中的 `sendDemoMessage()`。这些词只用于检查原型效果，不代表真实模型会按关键词执行，也不属于 [专家对话页 PRD](./experts_conversation_prd.md) 的功能规则。后续新增演示场景继续补充到本文件。

除注明“界面操作”或“内置样例”的条目外，在专家对话页新建任务并发送表中的文字即可触发；多数关键词按**包含匹配**，组合和优先级见文末。关键词场景的处理过程至少持续约 6 秒，中途说明或人工等待会使总时长更长。

所有新消息都必须包含去除首尾空白后的非空文字；可同时附带本地上传文件或引用资料，不能只发资料。

### 2.1 分类别工具活动（运行中）

下列 `演示工具：…` 均由本地事件模拟，不执行真实文件、命令、浏览器或外部服务操作。组标题以“正在推进：”或“处理经过：”引出摘要；组内活动行使用 6px 圆点，活动名称、操作对象和进展保持原有字体样式。活动组与活动行的展开图标紧邻各自文字；确实运行中的组标题与活动行有从左到右的灰色文字扫光，悬停／聚焦时暂停；等待启动及结束后保持静态。执行中组标题优先保留安全对象；活动行在对象后追加实际演示进展，展开详情归在对应活动行内。回合结束后，“处理经过”摘要只列活动名称，活动行和详情仍保留对象、进展及结果供查看。字段与降级规则见 [工具活动呈现对照表](./experts_conversation_tool_activity_matrix.md)。

### 2.2 工具终态与缺失事件

以下场景仍是本地模拟，用于核对单项工具与整个回合的状态边界。完成后展开“处理经过”，核对活动行及详情；回合状态行仍可为“已完成”。

| 触发词 | 工具活动预期 | 主要检查点 |
| --- | --- | --- |
| `演示工具：失败结果` | 未完成 | `success:false` 与错误内容结算同一工具；错误原因留在详情，回合不因单项失败自动变成处理失败。 |
| `演示工具：策略阻断` | 未获授权 | 明确阻断只影响该工具；不凭空生成用户审批回复。 |

## 3. 人工介入

请求在模拟文字输出后出现在输入区上方；请通过对应卡片回应。用户尚未作出决定时，右侧不生成回复气泡。

### 3.1 澄清

| 输入或操作 | 演示场景 | 主要检查点 | 备注 |
| --- | --- | --- | --- |
| `请澄清`，再提交回复 | 单题澄清 | 统一澄清浮窗接收回复；被接收的问答气泡随处理过程收起，回合继续。 |  |
| `请单选澄清` | 单题选项澄清 | 选项与“其他”文本回答均可提交；右上角显示 `1/1`。 |  |
| `请多选澄清` | 单题多选澄清 | 可选择多个选项，也可填写“其他”回答。 |  |
| `请多题澄清` | 多题澄清 | 逐题切换并显示当前题号／总题数；分别演示单选和多选，按题目保存答案。 |  |
| `已答多题澄清` | 恢复已接收答案 | 一题预置为“已接收”，只需回答其余题目。 |  |
| `请澄清`，点击“跳过澄清” | 主动跳过 | 记录用户跳过决定，专家继续；不显示为超时未答。 |  |
| `已答多题澄清`，点击“跳过剩余问题” | 部分已答后跳过 | 保留已接收的第一题，只对未回答题目记录空答。 |  |
| `演示澄清超时`，等待超时 | 未回答自动继续 | 澄清浮窗撤下；处理过程左侧显示超时记录，不生成用户回复气泡。 | 超时后专家依据已有资料继续。 |
| `演示澄清超时`，超时后点击“补充回答” | 当前回合补答 | 从超时记录打开同一澄清浮窗；仅在演示事件确认本回合接收后归入当前回合。 | 需在本回合结束前提交。 |
| `演示澄清超时`，回合结束后展开过程并补答 | 后续回合补答 | 新回合以人工介入气泡呈现补答；旧超时记录仍可追溯。 |  |

| `演示审批超时`，等待超时 | 审批未获回应 | 撤下待处理卡片，折叠过程内记录“审批已超时 · 未授权”；不生成拒绝气泡或执行活动。 |  |
| `演示并行审批` | 两项待处理请求 | 请求可逐项切换、独立允许或拒绝；先处理一项不清除另一项。 | 本地演示，不执行真实命令。 |

## 6. 组合、优先级与限制

| 规则 | 当前演示行为 | 使用建议 |
| --- | --- | --- |
| 关键词匹配 | 多数场景按包含匹配，不是精确指令。例如“分析审批失败原因”会同时命中审批和失败。 | 用表中短语单独测试，避免把模拟结果误认为专家的真实判断。 |
| 可组合场景 | `层级待办和目标等待` 同时更新待办与目标；`并行过程` 同时触发并行工具与中途说明。 | 先单独验收，再用组合词核对交互。 |
| 多个人工请求词 | 只选一种：凭据演示 → 管理员密码演示 → MCP 设置确认 → 审批 → 澄清。 | 避免在一条测试语中放入多类人工请求。 |
| 多种特殊活动词 | 只选一种：子代理 → 并行模型 → 思考。 | 并行模型是遗留调试触发，不属于当前产品需求。 |
| 工具类型冲突 | `进度` 优先使用网页提取；其次 `工具详情` 用命令，`文件差异` 用补丁，否则为普通读取活动。 | 不要把这几个关键词放进同一条测试语。 |
| 专项工具场景 | `演示工具：…` 优先于上述通用工具关键词，每条只演示一项对应工具；同一输入包含多个专项触发词时取目录中先匹配的一项。 | 一次只发送一个专项触发词，便于核对组标题、行与详情。 |
| 回复与结果优先级 | 人工请求优先于普通回复；无人工请求时，`失败/错误` 优先于 Markdown 与文件差异固定答复。失败或人工请求回合不会生成“待办结果”；输入引用资料不自动成为结果。 | 按目标场景选择尽量单一的输入。 |
| 本地数据边界 | 事件、文件和状态仅在浏览器本地；切换或离开任务会停止未完成的模拟流。 | 真实 Hermes 接入后的行为需另行验收。 |
