# 专家对话区知识检索展示方案

## 1. 原型设计

### 1.1 展示位置与活动归属

专家头像下依次展示回合状态、处理过程和最终回答。一次实际知识调用在处理过程里对应一条「检索知识」活动行。同一次调用的各个阶段更新原行，同轮多次调用按开始顺序各占一行。自动模式跳过检索或选择「本轮不用知识」时，按实际发生的其他活动和回答展示。

WeKnora 在一次知识调用内进行检索、读文档、查 Wiki 或分析表格，均更新该条「检索知识」活动。Hermes 单独调用 `read_file` 时，对话区另有一条「读取文件」活动，例如「读取文件 · 维护手册.pdf」。两类活动连续发生时可归入同一活动组，沿用中途说明和人工介入切分活动组的规则。 [专家对话页需求](./experts_conversation_prd.md)

### 1.2 活动组

活动组有进行中的活动时，组标题统一以「正在推进：」开头。知识项使用活动行的完整文案，随阶段更新。

| 场景 | 组标题 |
| --- | --- |
| 只有知识活动在进行 | 「正在推进：检索知识 · 阅读资料」。 |
| 知识活动正在读取结果 | 「正在推进：检索知识 · 正在读取结果」。 |
| 知识与其他活动同时进行 | 按开始顺序概括进行中的活动，例如「正在推进：检索知识 · 阅读资料、读取文件 · 维护手册.pdf」。 |
| 知识活动已收口，其他活动仍在进行 | 「正在推进：」后只概括仍在进行的活动，已收口的知识活动留在组内。 |
| 组内活动均已收口 | 显示「处理经过：检索知识」。同组还读了文件时显示「处理经过：检索知识、读取文件」。 |

进入「处理经过」后，部分完成、未找到资料、失败、取消、超时等状态只留在活动行，组标题里的知识项统一显示「检索知识」。活动行保留组摘要中属于自己的信息。组标题若展示文件名，展开后的文件活动行也展示同一文件名。整轮仍在生成回答时，活动组可以先收口，回合状态继续显示「处理中」。

回合运行或恢复时，外层处理过程保持展开，活动组可独立展开。整轮结束后，外层处理过程默认收起，最终回答仍显示在其下方。 [原型对话模板](../src/demo/pages/Chat.vue)

### 1.3 活动行

沿用原型的灰色圆点和运行中文字扫光。只有存在可查看的来源或可读的异常原因时才显示行内展开箭头。

| 阶段或结果 | 活动行文案 |
| --- | --- |
| `stage.type = accepted` | 检索知识 |
| `stage.type = understanding` | 检索知识 · 理解问题 |
| `stage.type = searching` | 检索知识 · 检索资料 |
| `stage.type = reading` | 检索知识 · 阅读资料 |
| `stage.type = wiki` | 检索知识 · 查询 Wiki |
| `stage.type = table_analysis` | 检索知识 · 分析表格 |
| `stage.type = summarizing` | 检索知识 · 整理结果 |
| `stage.type = completed`，结果正在读取 | 检索知识 · 正在读取结果 |
| `Result.status = success` | 检索知识 |
| `Result.status = partial` | 检索知识 · 部分完成 |
| `Result.status = empty` | 检索知识 · 未找到可用资料 |
| `failed` | 检索知识 · 检索失败 |
| `cancelled` | 检索知识 · 已取消 |
| `timed_out` | 检索知识 · 检索超时 |

受理后显示带扫光的「检索知识」。收到 `completed` 时停止检索扫光，读取结果期间显示相应提示。正常完成后显示静态的「检索知识」。阶段随实际事件出现，可以跳过或重复。`summarizing` 按收到时展示。结果接口尚未返回时维持读取提示，确认读取失败时可显示「来源暂不可用」及刷新入口。

```text
检索中
正在推进：检索知识 · 阅读资料 ▾
  ● 检索知识 · 阅读资料

读取结果中
正在推进：检索知识 · 正在读取结果 ▾
  ● 检索知识 · 正在读取结果

检索成功
处理经过：检索知识 ▾
  ● 检索知识 ▾
    查看本轮知识来源

检索无结果
处理经过：检索知识 ▾
  ● 检索知识 · 未找到可用资料
```

### 1.4 活动详情

展开活动行后，详情显示在该行下方，内容只对应本次知识调用。成功时优先展示少量可访问的来源标题和「查看本轮知识来源」入口。完整证据在「本轮知识来源」浮窗查看。部分完成或异常时，有可读原因才在详情补充，行上已有的状态文案无需重复。

| 场景 | 行内详情 | 数据依据 |
| --- | --- | --- |
| 检索进行中 | 当前阶段直接显示在活动行，省略详情箭头。 | `stage.type`。阶段帧提供状态。来源标题、片段和计算摘要在结果或证据接口可用后展示。 |
| 成功且有可访问证据 | 显示来源标题和「查看本轮知识来源」。只有来源入口可用时，详情可只显示入口。 | 从证据接口按 `knowledge_run_id` 选取本次调用的记录，取 `access = available` 的 `source.title` 或 `calculation_sources[].title`，按来源 ID 去重。 |
| 部分完成 | 有来源就按成功场景展示。存在可识别的警告时，可补一句原因，例如「知识侧摘要达到输出上限」。 | `Result.status = partial`、可识别的 `Result.warnings` 和可访问证据。 |
| 无可用资料 | 活动行显示「未找到可用资料」。没有额外信息时省略详情箭头。 | `Result.status = empty`。 |
| 失败、取消、超时 | 有可读的补充原因才开放详情，例如「当前没有访问所选资料的权限」。只有终态信息时，保留活动行上的状态文案即可。 | 通过 `stage.error_code` 映射已知原因。空码或未知码仅用已确认的终态文案。 |

来源标题、错误原因和来源入口按实际数据出现。活动行展开后可以是以下形式：

```text
处理经过：检索知识 ▾
  ● 检索知识 ▾
    ZX-42 维护手册
    传感器校准作业规范
    查看本轮知识来源
```

### 1.5 来源与最终回答

最终回复的引用显示为「[文档名称]」。标签取文档名的前四个字，超出时追加省略号。同一处引用多个文档时，各文档标签并排显示。同一处命中同一文档的多个片段时，合并为一个标签。悬停标签后，浮窗页眉左侧显示带后缀的文档名，右侧以小号灰字显示所属知识库。命中多个片段时，通过「片段 1」「片段 2」等小标签切换。浮窗最高 320 px，也会根据当前可用空间缩小，超长片段在正文区域滚动。表格证据可显示计算摘要。鼠标可移入浮窗继续查看，离开标签和浮窗后自动收起。

原型在输出含引用的正文片段之前，先关联该处引用的证据，并一次输出同一处的连续引用标记。流式输出到引用位置时，直接显示蓝色文档标签。右侧来源列表随已输出的引用更新。

点击活动详情的「查看本轮知识来源」或正文中的文档标签时，「本轮知识来源」浮窗出现在聊天页最右侧，可覆盖任务列表和工作空间，原有布局保持不变。浮窗距对话区上沿和输入区上沿各留 8 px，随输入区和窗口高度调整。切换筛选或来源数量变化时，来源列表在窗内独立滚动。点击关闭按钮、在浮窗内按 Esc 或点击窗外可关闭，切换任务时自动收起。

右侧浮窗汇总当前问答回合的证据，每个命中片段或计算摘要显示一张卡片。「全部」「已引用」「未引用」旁显示对应的片段数。已引用卡片按正文引用编号排序。未引用卡片按检索返回顺序排列，在「全部」中排在已引用卡片后面。

卡片首行左侧显示片段编号和含后缀的文档名，右侧以小号灰字显示所属知识库。片段正文或计算摘要直接展示，正文区最高 96 px，超出时在卡片内纵向滚动。左下角提供可用的原文入口，右下角显示引用状态。点击正文文档标签会定位并高亮该处引用的首个片段，从活动详情打开时定位到该调用的首条证据。资料失去访问权限时，浮窗提示「当前无法访问此资料」。

用户气泡上方的资料卡展示本轮提交的检索范围，浮窗展示实际返回的证据。 [正式前端来源组件](../../../工业万悟/des-ui/src/views/expert/components/task/ChatKnowledgePanel.vue) · [来源标题和片段提取](../../../工业万悟/des-ui/src/views/expert/utils/knowledge-citations.js)

## 2. 实现方案

### 2.1 与 Hermes 内置工具的接线差异

| 维度 | `use_knowledge` | Hermes 内置工具，例如 `read_file` |
| --- | --- | --- |
| 执行入口 | 当前 DES 知识回合由 Hermes 知识中间件执行预检索。插件也注册了模型工具 `use_knowledge(query, method_hint?)`。 | 模型发起工具调用，由 Hermes 工具执行器执行。 |
| 前端建行与更新 | 监听 `extension_knowledge_stage`，以 `knowledge_run_id` 关联同一次检索，用 `stage.type` 更新进度。自动预检索即使没有通用工具帧，也能按知识阶段建行。 | 专家 run SSE 用 `tool_started` 建行、`tool_completed` 更新。对应 Hermes 上游事件是 `tool.started`、`tool.completed`。当前专家 run 流没有通用的 `tool.progress` 帧。 |
| 活动的动作和对象 | 固定动作「检索知识」。运行阶段来自 `stage.type`。阶段帧不包含被读取的文件名、命中片段或计算结果。 | 动作由 `tool` 映射。操作对象可从实际可用的 `preview` 等字段提取，例如读文件路径。 |
| 结果与详情 | 终态阶段只说明调用结束。经授权的结果和证据由知识 API 返回，正文引用基于最终证据编号。 | 通用完成帧提供 `tool`、`duration`、`error`、`result`、`result_truncated`。`result` 是处理后的文本，最多 8,000 字符。按工具类型从实际可用字段生成详情。 |
| 对话内收口 | 知识终态更新知识活动。整轮回合由 `run_completed`、`run_failed` 或 `run_cancelled` 收口。 | 工具完成只更新所属活动。整轮回合仍由 run 终态收口。 |

原型已有的 `tool.start`、`tool.progress`、`tool.complete` 是浏览器生成的本地演示事件。正式的知识阶段帧与普通工具帧共用 Hermes 的会话 `seq`，各自按事件名称解析。WeKnora 的普通问答 SSE 和内部重排、合并、筛选等步骤也有自己的事件或处理逻辑。DES 的知识活动按受管 `NativeEvent` 契约展示。

### 2.2 运行流程与字段接口

服务端流程为 DES 派发知识回合，Hermes 执行中间件并请求 DES 私有 `POST /internal/knowledge/v3/invoke`，DES 启动 WeKnora 检索并把阶段投递到同一条 Hermes run 流。知识调用结束后，DES 读取和保存结构化结果。Hermes 登记证据，生成回答并确认引用，最后发出 `run_completed`。 [DES 知识调用](../../../工业万悟/des/digital-employee-service/internal/knowledgev3/engine/invoke.go) · [DES 接口契约](../../../工业万悟/des/docs/weknora-v3/formal-current/des.openapi.json)

下表的 `{turn}` 代表 `/api/des/v3/runs/{des_run_id}/messages/{message_id}`。

| 时机 | 接口或事件 | 字段与用途 |
| --- | --- | --- |
| 准备和派发 | `POST /api/des/v3/experts/{expert_id}/knowledge/messages:prepare` → `PUT {turn}/knowledge-scope` → `POST {turn}:dispatch` | 准备回执给出 DES `run_id`、`message_id` 和初始范围。提交封存的范围版本和哈希、问题与附件 ID。派发回执返回 `hermes_run_id`，待确认时查询 `GET {turn}/dispatch`。 |
| 接收知识阶段 | `GET /api/v1/experts/{expert_id}/runs/{hermes_run_id}/events` 的 `extension_knowledge_stage` | 上游事件名为 `extension.knowledge.stage`。帧的 JSON 载荷中，`data.message_id` 关联用户消息，`data.knowledge_run_id` 关联知识调用，`data.tool_call_id` 保留调用关联，`data.seq` 是 Hermes 会话序号。 |
| 映射阶段文案 | 同一阶段帧的 `data.stage` | `type` 为上表所列阶段，`error_code` 可映射为用户可读原因。`count` 可空，部分路径表示工具步数。内层 `stage.seq` 是 WeKnora 原生序号。 |
| 确认知识结果 | `GET {turn}/knowledge-runs` 或 `GET /api/des/v3/knowledge-runs/{knowledge_run_id}` | 用 `knowledge_run_id` 匹配活动，按 `status` 更新行文案。`sources`、`hits`、`calculations` 描述结构化结果，允许有计算或来源而无文本命中。 |
| 读取来源 | `GET /api/des/v3/runs/{des_run_id}/knowledge/evidence?message_id=...` | 分页读取证据。用 `knowledge_run_id` 定位调用，用 `access` 约束内容，用 `answer_message_id`、`final_citation_number` 关联最终回答。 |
| 查看原文 | `GET /api/des/v3/runs/{des_run_id}/knowledge/citations/{evidence_id}/content?source_id=...` | 读取当前可访问的原文，按响应类型预览或下载。 |
| 展示最终回答 | 同一条 SSE 的 `run_completed` | `output` 写入助手正文。整轮结束后刷新结果和证据，补齐最终引用。 |
| 停止或恢复 | `POST {turn}:cancel`、`GET /api/v1/experts/{expert_id}/runs/{hermes_run_id}`、`GET /api/v1/conversations/{conversation_id}/messages` | 停止本轮、查询 run 状态、加载历史。知识结果和证据按历史消息的 `payload.knowledge_scope` 查询。 |

SSE 的 `id`、载荷顶层 `seq`、阶段载荷内的 `data.seq` 对应同一 Hermes 会话序号，以十进制字符串传输。前端按该序号排序和去重。`des_run_id` 来自知识上下文，用于知识 API。`hermes_run_id` 来自派发回执，用于订阅和查询 run。`knowledge_run_id` 对应一次实际检索。 [统一序号分配](../../../工业万悟/hermes-agent/gateway/api_run_store.py) · [前端知识 API](../../../工业万悟/des-ui/src/api/knowledge.js)

## 3. 原型落地与验收

### 3.1 原型落地

1. `src/demo/knowledge-activity-scenes.js` 定义检索场景及来源样例，`src/demo/state.js` 负责模拟阶段帧、结果接口回执、证据和最终回复。知识进度使用与正式阶段契约一致的字段，演示中保留同一个调用 ID。
2. 在 `src/demo/conversation-turns.js` 按调用 ID 建立和更新知识活动，复用现有活动组。保存固定动作、当前阶段、结果状态和可查看的证据入口。「正在推进」的摘要复用活动行文案，「处理经过」的摘要读取固定动作。
3. 在 `src/demo/pages/Chat.vue` 和 `src/demo/chat.scss` 复用现有圆点、扫光、展开箭头和限高滚动。用本地证据样例演示行内来源摘要、可读异常原因、右侧来源浮窗、原文入口和正文引用定位。

#### 演示触发词

在「质量分析专家」中打开或新建任务，单独发送下表中的完整触发词。场景使用本地阶段和证据样例，可在运行时展开活动组观察阶段，回合结束后重新展开「处理经过」查看详情。

| 触发词 | 演示效果 |
| --- | --- |
| `演示工具：检索知识` | 检索与读取结果合计约 7.6 秒，理解问题、检索资料、阅读资料、整理结果和读取结果分别停留约 1.1 至 1.7 秒。同一活动行随阶段更新，最终回复分段展示校准检查、测点验证和抽检复核。悬停维护手册标签可切换 3 个片段，第一个片段可在浮窗内滚动。「本轮知识来源」汇总 4 份资料的 7 条已引用证据和 1 条未引用证据，切换到「未引用」也可验证长片段在卡片内滚动。 |
| `演示工具：检索知识部分完成` | 活动行显示「部分完成」，详情保留已获得的来源并说明摘要达到输出上限。 |

| `演示工具：检索知识取消`／`演示工具：检索知识超时` | 分别显示「已取消」「检索超时」，活动组收口为「处理经过：检索知识」。 |
| `演示工具：多次检索知识` | 同轮先查询 Wiki，再分析表格，各占一行。两行的来源入口分别打开对应证据，正文引用分别定位 Wiki 命中片段和表格计算摘要。 |
| `演示过程` | 知识已启用时，第一组同时演示「读取文件」和「检索知识」，知识阶段和文件名分别保留在各自的活动行。最终回答可通过引用查看来源。 |

也可在输入区点击 `@`，从「知识中心」直接引用「质量标准与规范」知识库，或打开该库选中「良率统计口径说明.md」，然后发送普通问题，例如「良率是怎么计算的？」。提交后自动出现「检索知识」。引用知识库时，来源来自所选库内的演示文档。只引用指定文档时，来源限定为所选文档。同轮多选会合并检索范围，重叠文档只返回一份证据。发送 `演示过程` 时也可附带知识引用，第一组按本轮范围展示来源。

选中资料后可继续编辑问题，发送时开始检索。单独引用工作空间文件或上传附件时，沿用各自的资料卡和发送规则。

### 3.2 正式前端接入

1. `des-ui` 当前每条用户消息只保存一个最新知识阶段，阶段条挂在用户消息下。将知识展示状态改为按用户消息和 `knowledge_run_id` 保存，收到首帧时把该调用加入专家的过程项。活动行按开始顺序排列，按最新序号更新。普通工具继续走现有事件解析。在受管知识回合里，同一次知识调用的活动由知识阶段或结果驱动，防止通用 `use_knowledge` 帧再建一条活动。
2. 将知识活动与现有思考、工具步骤一起传给过程组。知识行提供完整文案和固定动作两项，分别用于「正在推进」和「处理经过」的组摘要。来源浮窗沿用 `ChatKnowledgePanel` 的证据查询和引用定位。行内来源摘要从本次调用的可访问证据提取，部分完成或异常详情从已知的 `warnings` 或 `stage.error_code` 映射。有摘要、来源入口或可读原因时显示详情箭头。从活动行打开时传入 `knowledge_run_id`，从正文打开时按回答与引用编号定位。
3. 阶段收到 `completed` 时刷新知识结果。DES 可能仍在读取并保存结构化结果，接口未就绪时保留「正在读取结果」。整轮终态后再刷新结果与证据。阶段已确认失败、取消或超时时，按该终态显示行文案。回合状态由对话 run 独立更新。
4. 重连时用序号避免重复建行。受管 SSE 支持 `Last-Event-ID`，当前专家 SSE 前端接线需要保存并传递游标才能按游标续接。历史页用已保存的调用结果恢复终态，有可恢复的事件时再恢复阶段和顺序。自动跳过检索、派发失败且没有调用记录等场景按已有事实展示。

### 3.3 验收场景

| 场景 | 预期 |
| --- | --- |
| 单次知识调用经过理解、检索、阅读和读取结果 | 只有一条活动行。「正在推进：」后的摘要与该行文案一致。 |
| 普通问题随知识中心引用发送 | 自动创建一条知识活动，组标题在「正在推进：」后显示当前检索阶段。用户消息保留引用资料卡，活动详情与正文引用指向本轮所选范围内的证据。 |
| 正常完成且有引用 | 组标题为「处理经过：检索知识」，行只显示「检索知识」，可通过该行和正文引用查看来源。 |
| 部分完成、空结果、失败、取消、超时 | 具体状态只显示在活动行，处理经过的知识项仍是「检索知识」。 |
| 展开活动详情 | 有可访问证据时显示来源标题与入口，有已知异常原因时可展开查看。无来源且无补充原因时省略详情箭头。 |
| 打开本轮知识来源 | 聊天页最右侧出现临时浮窗，可覆盖任务列表和工作空间，汇总本轮全部来源。点击正文文档标签可定位证据。 |
| 悬停最终回复的文档标签 | 浮窗显示知识库、完整文档名及后缀、命中片段或计算摘要。同一处引用多个文档时逐个显示标签，同一文档有多个片段时可切换。 |
| 与 Hermes `read_file` 同组 | 有两条活动行。WeKnora 的 `reading` 只更新知识行，Hermes 读取文件行保留自己的文件名。 |
| 同轮两次检索、旧帧重放或恢复历史 | 两条活动的来源入口打开同一个本轮列表，并定位到各自证据。重复帧不新增活动，过期帧不回退状态，历史使用已保存结果恢复。 |
| 自动跳过检索 | 直接呈现实际发生的对话活动和最终回答。 |
