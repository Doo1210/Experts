**研发接入规则**

RAG 和 Wiki 共用 DES 证据接口，前端逐条判断。RAG 文档片段为 `item.kind === "hit"` 且 `item.source.kind === "document"`，正文取 `hit.text`。Wiki 页面为 `item.kind === "source"` 且 `item.source.kind === "wiki"`，悬停时通过现有原文接口读取 `body`，生成正文节选；点击「查看」阅读完整页面。表格计算保留独立的 `calculation` 类型，摘要取 `calculation.summary`。正文引用按 `answer_message_id` 和 `final_citation_number` 关联证据，查看原文时传 `evidence_id` 和 `source.id`。 [2.2 运行流程与字段接口](#22-运行流程与字段接口) · [3.2 正式前端接入 · 引用类型判定](#引用类型判定)

**原型验收**

用 `演示工具：长详情` 检查日志预览和浮窗滚动，用 `演示工具：修改文件` 检查活动详情和产出卡片的差异入口。对话页 PRD 已同步更新。 [专家对话页 PRD](./experts_conversation_prd.md#5333-处理活动)

## 1. 原型设计

### 1.1 展示位置与活动归属

专家头像下依次展示回合状态、处理过程和最终回答。一次实际知识调用在处理过程里对应一条「检索知识」活动行。同一次调用的各个阶段更新原行，同轮多次调用按开始顺序各占一行。自动模式跳过检索或选择「本轮不用知识」时，按实际发生的其他活动和回答展示。

WeKnora 在一次知识调用内进行检索、读文档、查 Wiki 或分析表格，均更新该条「检索知识」活动。Hermes 单独调用 `read_file` 时，对话区另有一条「读取文件」活动，例如「读取文件 · 维护手册.pdf」。两类活动连续发生时可归入同一活动组，沿用中途说明和人工介入切分活动组的规则。 [专家对话页需求](./experts_conversation_prd.md)

### 1.2 活动组

活动组有进行中的活动时，组标题统一以「正在推进：」开头。知识项使用活动行的完整文案，随阶段更新。

| 场景 | 组标题 |
| --- | --- |
| 只有知识活动在进行 | 「正在推进：检索知识 · 阅读文档」。 |
| 知识活动正在读取结果 | 「正在推进：检索知识 · 正在读取结果」。 |
| 知识与其他活动同时进行 | 按开始顺序概括进行中的活动，例如「正在推进：检索知识 · 阅读文档、读取文件 · 维护手册.pdf」。 |
| 知识活动已收口，其他活动仍在进行 | 「正在推进：」后只概括仍在进行的活动，已收口的知识活动留在组内。 |
| 组内活动均已收口 | 显示「处理经过：检索知识」。同组还读了文件时显示「处理经过：检索知识、读取文件」。 |

进入「处理经过」后，部分完成、未找到资料、失败、取消、超时等状态只留在活动行，组标题里的知识项统一显示「检索知识」。活动行保留组摘要中属于自己的信息。组标题若展示文件名，展开后的文件活动行也展示同一文件名。整轮仍在生成回答时，活动组可以先收口，回合状态继续显示「处理中」。

回合运行或恢复时，外层处理过程保持展开，活动组可独立展开。整轮结束后，外层处理过程默认收起，最终回答仍显示在其下方。 [原型对话模板](../src/demo/pages/Chat.vue)

### 1.3 活动行

沿用原型的灰色圆点和运行中文字扫光。有过程记录、结果或可读异常原因时显示展开箭头，运行中即可展开。

| 阶段或结果 | 活动行文案 |
| --- | --- |
| `stage.type = accepted` | 检索知识 |
| `stage.type = understanding` | 检索知识 · 理解问题 |
| `stage.type = searching` | 检索知识 · 检索片段 |
| `stage.type = reading` | 检索知识 · 阅读文档 |
| `stage.type = wiki` | 按实际工具显示「检索知识 · 检索 Wiki」或「检索知识 · 阅读 Wiki」。 |
| `stage.type = table_analysis` | 检索知识 · 分析表格 |
| `stage.type = summarizing` | 检索知识 · 整理结果 |
| `stage.type = completed`，结果正在读取 | 检索知识 · 正在读取结果 |
| `Result.status = success` | 检索知识 |
| `Result.status = partial` | 检索知识 · 部分完成 |
| `Result.status = empty` | 检索知识 · 未找到可用资料 |
| `failed` | 检索知识 · 检索失败 |
| `cancelled` | 检索知识 · 已取消 |
| `timed_out` | 检索知识 · 检索超时 |

### 1.4 活动详情

#### 1.4.1 过程时间线

一次知识调用对应一条「检索知识」活动。详情从首个实际步骤起可展开，按调用顺序追加记录。左侧显示对应动作的小图标，以浅灰竖线连接各步骤。运行中的最后一步展示动作和参数，完成后在该步下方补结果小字。再次检索、再次阅读及无匹配步骤分别保留。

详情展开后随内容增高，统一跟随对话区滚动。用户展开期间新步骤持续追加，向上查看历史时保留阅读位置。步骤间距 9 px，动作行高 20 px，结果小字 11 px、行高 1.5，与动作间距 1 px；不另设详情内部滚动区。检索结束后在末尾以完成图标承接「完成检索」及总结内容。

```text
● 检索知识 ▾
  理解图标  理解问题 「ZX-42 校准要求」
  │         已完成问题理解
  检索图标  检索片段 「ZX-42 校准与零点校验要求」
  │         命中 6 个片段，来自 3 份文档
  文件图标  阅读文档 ZX-42 维护手册.md
  │         已读取 3 个片段
  检索图标  检索 Wiki 「校准记录 ｜ 复核要求」
  │         找到 1 个 Wiki 页面
  书本图标  阅读 Wiki 校准记录与复核
  │         已读取页面
  检索图标  检索片段 「ZX-42 高量程偏差处理」
  │         无匹配
  文件图标  阅读文档 传感器校准作业规范.md
  │         已读取 2 个片段
  文件图标  阅读文档 校准记录交接指南.md
  │         已读取 1 个片段
  表格图标  分析表格 本周抽检汇总.csv
  │         已完成分析，返回 4 条结果
  完成图标  完成检索
            已查到校准和记录要求，高量程偏差处理仍需进一步核对。
            本轮引用知识：6 个片段、1 个 Wiki 页面、1 项计算结果（可点击）
```

#### 1.4.2 动作与参数

| 动作 | 对应工具 | 参数形式 |
| --- | --- | --- |
| 理解问题 | `query_understand` | 中性灰文字，实际查询内容放在一对「」内。 |
| 检索片段 | `search_knowledge` | 所有实际查询放在同一对「」内，以 `｜` 分隔，例如「关键词 1 ｜ 关键词 2」。长文本省略，悬停显示全文，保留首尾括号。 |
| 阅读文档 | `read_document` | 普通灰色文字显示带后缀的文件名。超长文件名省略主体、保留后缀。 |
| 检索 Wiki | `wiki_search` | 与文档检索相同的查询样式。 |
| 阅读 Wiki | `wiki_read_page` | 普通灰色文字显示页面标题。同次读取多个页面时并排展示，可换行。 |
| 分析表格 | `data_analysis` | 普通灰色文字显示带后缀的文件名。 |

过程参数重点展示查询内容及具体阅读对象，不展示知识库列表。文档、Wiki 和表格名称使用相同的中性灰色文字，无名称图标、彩色背景、边框或点击交互。超长名称悬停显示完整文字。左侧时间线仍用动作图标和竖线连接步骤。名称从当前可访问的资料元数据解析。`query` 可以是完整问题，也可能是正则表达式；不自行按空格或 `|` 拆词。只有真实的多项查询数组才以 ` ｜ ` 拼接，整体包裹一次「」。各动作的具体取值见 [3.2.2](#322-动作与-args-取值)。

#### 1.4.3 每步执行结果

结果使用小号灰字放在动作和参数下方。有返回结果时展示命中片段数、文档数、已读取片段数、Wiki 页面数或表格查询返回行数。无匹配展示「无匹配」。部分读取、失败、取消和超时按实际结果显示简短文案。当前执行步骤只显示动作和参数，不添加「正在读取」等状态小字。过程结果数量取明确的结果字段，`stage.count` 按其真实语义处理。字段来源和文案见 [3.2.3](#323-结果小字取值)。

#### 1.4.4 完成检索

知识结果读取完成后，在全部步骤之后显示完成图标和「完成检索」。文字取本次调用的检索总结，默认最多四行，超出可展开。下方以可点击的一行「本轮引用知识：N 个片段、M 个 Wiki 页面、K 项计算结果」统计本轮全部知识调用返回的可访问证据，零项省略。点击打开「本轮引用知识」浮窗，默认展示全部来源。同一文档的不同片段分别计数，重复读取同一片段计一次。总结与计数字段见 [3.2.4](#324-完成检索字段)。

无结果时显示本次范围内未找到可用资料的总结。部分完成时保留已获得的总结和实际结果数量，并显示已知原因。失败、取消或超时保留已经发生的过程和明确终态。每次知识调用保留自己的总结文字；「本轮引用知识」数量和浮窗统一汇总当前用户消息对应的全部知识调用。

### 1.5 来源与最终回答

#### 1.5.1 正文引用

最终回复的引用使用带图标和细边框的小标签。RAG 用蓝色文件图标和文档名，Wiki 用绿色书本图标和页面名。标题最多显示前五个字符，超出追加省略号。同一处引用多个来源时，标签并排显示。同一处命中同一文档的多个片段时，合并为一个标签。

原型在输出含引用的正文片段之前，先关联该处引用的证据，并一次输出同一处的连续引用标记。流式输出到引用位置时，直接显示对应类型的标题标签。点击标签先打开「本轮引用知识」浮窗，并高亮、滚动到该处引用对应的卡片。

#### 1.5.2 引用悬浮窗

悬停标签后，浮窗页眉显示完整标题，标题右侧紧跟小号灰字的知识库名称，右上角显示「chunk」或「Wiki」标签。RAG 文档名保留后缀，下方显示该处的命中片段或表格计算摘要。同一处引用多个片段时，通过「片段 1」「片段 2」等小标签切换。Wiki 为页面级证据，展示当前授权页面的正文节选：去除 Markdown 排版标记，保留可读的段落、列表及表格文字；不伪造 RAG 片段或片段切换 Tab。原型使用同一页面原文样例生成节选，正式接入的取值见「引用类型判定」。原文可用时，浮窗左下角显示「查看」，点击打开对应的原文弹窗。浮窗最高 320 px，也会根据当前可用空间缩小，超出可用高度的片段以省略号收尾。鼠标可移入浮窗继续查看，离开标签和浮窗后自动收起。

#### 1.5.3 引用查看入口

「完成检索」下方的「本轮引用知识：…」数量行和最终回复的引用标签，点击后均先打开「本轮引用知识」浮窗。数量行默认查看全部来源；点击正文标签时切换到「全部」，高亮对应卡片并在列表内滚动定位。同一处合并多个片段的标签先定位其中最早的引用片段，其他片段仍保留独立卡片。

浮窗位于对话页最右侧，可覆盖任务列表和工作空间，不挤压对话内容。上方间隔 8 px，底部距离输入框上边缘 8 px；高度随页面及输入框可用空间固定，不随筛选后的卡片数量变化。提供关闭按钮，点击浮窗外部或按 Escape 关闭，关闭后可回到触发入口。

「全部／已引用／未引用」三个筛选项均显示数量。RAG 一条片段一张卡，Wiki 页面和计算结果各自保留卡片；已引用内容按正文最终引用顺序排列，未引用内容列在后面。卡片标题与知识库名称同排，右上角为浅色「chunk」或「Wiki」，正文最多三行省略，Wiki 展示页面正文节选。左下角「查看」打开原文弹窗，右下角标注已引用／未引用。列表可滚动，单张卡片内容不单独滚动。

活动详情中的文档、Wiki 页面和表格名称仍为普通灰色说明文字，不提供点击入口。引用悬浮窗左下角的「查看」直接打开原文弹窗。资料失去访问权限时提示当前不可用。

用户气泡上的知识资料卡展示提交范围，过程中的对象和正文引用依据本次实际执行和证据展示。

#### 1.5.4 原文弹窗

点击「本轮引用知识」浮窗卡片或引用悬浮窗中的「查看」，打开居中原文弹窗。弹窗页眉中，文档名或 Wiki 页名在上，知识库名称在下一行左对齐，右侧显示「chunk」或「Wiki」标签。Wiki 原文在弹窗内按 Markdown 排版。弹窗底部仅提供「关闭」按钮。

## 2. 实现方案

### 2.1 与 Hermes 内置工具的接线差异

| 维度 | `use_knowledge` | Hermes 内置工具，例如 `read_file` |
| --- | --- | --- |
| 执行入口 | 当前 DES 知识回合由 Hermes 知识中间件执行预检索。插件也注册了模型工具 `use_knowledge(query, method_hint?)`。 | 模型发起工具调用，由 Hermes 工具执行器执行。 |
| 前端建行与更新 | 监听 `extension_knowledge_stage`，以 `knowledge_run_id` 关联同一次检索，用 `stage.type` 更新进度。自动预检索即使没有通用工具帧，也能按知识阶段建行。 | 专家 run SSE 用 `tool_started` 建行、`tool_completed` 更新。对应 Hermes 上游事件是 `tool.started`、`tool.completed`。当前专家 run 流没有通用的 `tool.progress` 帧。 |
| 活动的动作和对象 | 固定动作「检索知识」。运行阶段来自 `stage.type`。阶段帧不包含被读取的文件名、命中片段或计算结果。 | 动作由 `tool` 映射。操作对象可从实际可用的 `preview` 等字段提取，例如读文件路径。 |
| 结果与详情 | 终态阶段只说明调用结束。经授权的结果和证据由知识 API 返回，正文引用基于最终证据编号。 | 通用完成帧提供 `tool`、`duration`、`error`、`result`、`result_truncated`。`result` 是处理后的文本，最多 8,000 字符。按工具类型从实际可用字段生成详情。 |
| 对话内收口 | 知识终态更新知识活动。整轮回合由 `run_completed`、`run_failed` 或 `run_cancelled` 收口。 | 工具完成只更新所属活动。整轮回合仍由 run 终态收口。 |

原型已有的 `tool.start`、`tool.progress`、`tool.complete` 是浏览器生成的本地演示事件。正式的知识阶段帧与普通工具帧共用 Hermes 的会话 `seq`，各自按事件名称解析。WeKnora 的普通问答 SSE 和内部重排、合并、筛选等步骤也有自己的事件或处理逻辑。DES 的知识活动按受管 `NativeEvent` 契约展示。

### 2.2 运行流程与字段接口

服务端流程为 DES 派发知识回合，Hermes 执行中间件并请求 DES 私有 `POST /internal/knowledge/v3/invoke`，DES 启动 WeKnora 检索并把阶段投递到同一条 Hermes run 流。知识调用结束后，DES 读取和保存结构化结果。Hermes 登记证据，生成回答并确认引用，最后发出 `run_completed`。 [DES 知识调用](../../../工业万悟/des/digital-employee-service/internal/knowledgev3/engine/invoke.go) · [DES 接口契约](../../../工业万悟/des/docs/weknora-v3/formal-current/des.openapi.json)

下表的 `{turn}` 代表 `/api/des/v3/runs/{des_run_id}/messages/{message_id}`。

| 时机 | 接口或事件 | 字段与用途 |
| --- | --- | --- |
| 准备和派发 | `POST /api/des/v3/experts/{expert_id}/knowledge/messages:prepare` → `PUT {turn}/knowledge-scope` → `POST {turn}:dispatch` | 准备回执给出 DES `run_id`、`message_id` 和初始范围。提交封存的范围版本和哈希、问题与附件 ID。派发回执返回 `hermes_run_id`，待确认时查询 `GET {turn}/dispatch`。 |
| 接收知识阶段 | `GET /api/v1/experts/{expert_id}/runs/{hermes_run_id}/events` 的 `extension_knowledge_stage` | 上游事件名为 `extension.knowledge.stage`。帧的 JSON 载荷中，`data.message_id` 关联用户消息，`data.knowledge_run_id` 关联知识调用，`data.tool_call_id` 保留调用关联，`data.seq` 是 Hermes 会话序号。 |
| 映射阶段文案 | 同一阶段帧的 `data.stage` | `type` 为上表所列阶段，`error_code` 可映射为用户可读原因。`count` 可空，部分路径表示工具步数。内层 `stage.seq` 是 WeKnora 原生序号。 |
| 确认知识结果 | `GET {turn}/knowledge-runs` 或 `GET /api/des/v3/knowledge-runs/{knowledge_run_id}` | 用 `knowledge_run_id` 匹配活动，按 `status` 更新行文案。`sources`、`hits`、`calculations` 描述结构化结果，允许有计算或来源而无文本命中。 |
| 读取来源 | `GET /api/des/v3/runs/{des_run_id}/knowledge/evidence?message_id=...` | 分页读取证据。用 `knowledge_run_id` 定位调用，用 `access` 约束内容，用 `answer_message_id`、`final_citation_number` 关联最终回答。 |
| 读取原文 | `GET /api/des/v3/runs/{des_run_id}/knowledge/citations/{evidence_id}/content?source_id=...` | 读取当前可访问的原文，用于弹窗预览。 |
| 展示最终回答 | 同一条 SSE 的 `run_completed` | `output` 写入助手正文。整轮结束后刷新结果和证据，补齐最终引用。 |
| 停止或恢复 | `POST {turn}:cancel`、`GET /api/v1/experts/{expert_id}/runs/{hermes_run_id}`、`GET /api/v1/conversations/{conversation_id}/messages` | 停止本轮、查询 run 状态、加载历史。知识结果和证据按历史消息的 `payload.knowledge_scope` 查询。 |

SSE 的 `id`、载荷顶层 `seq`、阶段载荷内的 `data.seq` 对应同一 Hermes 会话序号，以十进制字符串传输。前端按该序号排序和去重。`des_run_id` 来自知识上下文，用于知识 API。`hermes_run_id` 来自派发回执，用于订阅和查询 run。`knowledge_run_id` 对应一次实际检索。 [统一序号分配](../../../工业万悟/hermes-agent/gateway/api_run_store.py) · [前端知识 API](../../../工业万悟/des-ui/src/api/knowledge.js)

### 3.2 正式前端接入

1. `des-ui` 当前每条用户消息只保存一个最新知识阶段，阶段条挂在用户消息下。将知识展示状态改为按用户消息和 `knowledge_run_id` 保存，收到首帧时把该调用加入专家的过程项。活动行按开始顺序排列，按最新序号更新。普通工具继续走现有事件解析。在受管知识回合里，同一次知识调用的活动由知识阶段或结果驱动，防止通用 `use_knowledge` 帧再建一条活动。
2. 将知识活动与思考、工具步骤一起传给过程组。以 `message_id + knowledge_run_id` 保存完整步骤，在步骤开始时追加动作和参数，在返回时按步骤身份更新结果。动作按实际工具名区分文档检索、文档阅读、Wiki 检索、Wiki 阅读和表格分析。
3. WeKnora 内部工具开始和结果事件已包含调用标识、参数和部分结构化结果。需归并成可查询的过程详情，由 DES 保存并提供实时更新及历史恢复。当前 `NativeEvent` 契约仅有阶段、序号、可选计数和错误码，过程详情通过新增契约接入。
4. 阶段收到 `completed` 后读取知识结果，确认保存成功后展示「完成检索」及总结。正文引用以最终证据编号和当前访问权限为准，点击时先打开本轮知识浮窗；点击卡片「查看」时请求引用原文接口。知识结果和整轮最终回复分别收口。
5. 重连按序号去重，历史从保存的过程详情恢复。先前版本缺少过程记录时展示可恢复的总结和证据。步骤及其资料元数据沿用知识结果的访问校验。

#### 3.2.1 过程记录字段

**现有源码边界。** WeKnora 内部 `AgentToolCallData` 提供 `tool_call_id`、`tool_name`、`arguments`，`AgentToolResultData` 提供相同调用标识及 `success`、`data`、`error`、`output`、`duration_ms`。受管集成目前将它们投影为 `NativeEvent` 阶段，公开帧没有完整参数、逐步结果或文件名。内部 `ReadChunks` 标记为 `json:"-"`，不能作为前端返回字段。需要在 WeKnora／DES 侧归一化并持久化过程，再补充授权的过程详情查询和增量通知契约，支持运行中查询及刷新后的历史恢复。以下是**待实现的过程详情建议结构**，并非现有接口已经返回的字段。 [内部工具事件](../../../工业万悟/weknora/internal/event/event_data.go#L179) · [受管阶段投影](../../../工业万悟/weknora/internal/application/service/wanwu_runtime_execute.go#L189) · [现有 NativeEvent](../../../工业万悟/des/digital-employee-service/internal/knowledgev3/native/types_generated.go#L347)

外层以 `message_id + knowledge_run_id` 定位活动，`steps[]` 保存该调用内的过程记录。建议每条记录包括：

| 字段 | 类型与取值 | 来源与前端用途 |
| --- | --- | --- |
| `id` | 字符串，稳定且非空 | 取 WeKnora 内部工具调用的 `tool_call_id`，用于开始／结束合并。与外层知识调用的 `data.tool_call_id` 分开保存；外层标识不能代替每步 ID。 |
| `order_seq`、`update_seq` | 十进制字符串 | 由过程记录契约提供同一知识调用内的排序序号。前者为开始顺序，后者为最近更新序号。按前者排列，按后者去重和更新；结束事件更新原行，不重新追加。同工具再次调用使用新 ID。序号与 Hermes SSE 序号分别处理。 |
| `tool` | 工具名字符串 | 来自 `tool_name`，按下节映射动作和图标。保留原工具名用于排查。 |
| `status` | `running / complete / error / interrupted / unknown` | 开始事件为 `running`；结果的 `success=true` 为 `complete`，明确失败为 `error`；调用取消／超时而该步未结束时为 `interrupted`；历史缺失结束回执为 `unknown`。整次检索结果的 `partial` 等状态单独保存在活动上。 |
| `args.queries` | 字符串数组，可空 | 从实际查询参数归一化，详见下节。前端用 `queries.join(" ｜ ")` 后整体包裹一对「」。 |
| `args.targets[]` | 对象数组，可空 | 具体阅读／分析对象，至少有 `kind`（`document / wiki`）、资源内对象 `id` 和可读 `title`；文档有真实 `file_name` 时一并返回。内部保留知识库身份以区分同名对象，过程行不显示知识库名称。 |
| `result` | 可空对象 | 未结束时为空；结束后包含明确的计数、`no_match`、`partial`、`error_code` 等归一化结果，详见 3.2.3。数字缺失保留空值，不补成 0。前端据此生成结果小字。 |

活动详情不提供原文查看，因此无需为该展示补充 `args.targets[].source_id / evidence_id`。正文引用及其悬浮窗继续使用现有证据字段和原文接口。

`result.matched_chunk_count / document_count / read_chunk_count / matched_page_count / read_page_count / row_count` 为非负整数或空值。`no_match`、`partial` 为布尔值，仅在已确认时返回；`error_code` 为可空的受控错误码。`knowledge_search` 别名额外保留 `count / candidate_count / doc_count / web_count`，均为非负整数或空值，不强行转换成文档份数。

      "update_seq": "4",

      "args": {
        "queries": ["ZX-42 校准与零点校验要求"],

#### 3.2.3 结果小字取值

以下计数由服务端在工具结果产生处归一化到建议结构的 `result`，前端按模板显示。每步计数只描述该次执行，末尾总数另外去重。

| 动作 | 结果字段来源与归一化 | 小字模板 |
| --- | --- | --- |
| 理解问题 | 对应结果 `success=true`。 | `已完成问题理解`。 |
| 检索片段（`search_knowledge`） | 从 `data.results[]` 筛出文档片段，按知识库身份和 `chunk_id` 去重，记为 `matched_chunk_count`；所属 `(knowledge_base_id, knowledge_id)` 去重为 `document_count`。原始 `data.count` 可能含 FAQ 等类型，只有结果全是文档片段时才可直接沿用。 | `命中 N 个片段，来自 M 份文档`；文档数未知则只写 `命中 N 个片段`。确认成功且无任何匹配为 `无匹配`。若只有 FAQ 等其他结果，按其实际类型展示，不能写成无匹配或文档片段。 |
| 检索片段（`knowledge_search`） | 此进度结果的 `data.count` 是实际保留的相关内容数，`candidate_count` 是未保留的候选数，`doc_count / web_count` 是内容来源分类计数，不能当作文档份数。单独保留这些计数。 | `检索到 N 条相关内容`；保留数为 0 且候选数大于 0 时显示 `命中 N 条候选，相关性不足，未用于回答`；均为 0 才显示 `无匹配`。 |
| 阅读文档 | `read_chunk_count = data.fetched_chunks`；缺失时可从实际返回的 `chunks[]` 或 `chunk_ids[]` 计算。`total_chunks` 是整份文档规模，不能当作本次读取数量。`data.truncated` 或 `next_offset` 提示还有内容时保留部分读取信息。 | `已读取 N 个片段`；有后续内容时补 `，后续内容可继续读取`。过滤读取明确无匹配时为 `无匹配`；确认空文档则为 `暂无可读片段`。 |
| 检索 Wiki | `matched_page_count` 来自本次实际返回的搜索页面，按知识库身份＋页面 ID／slug 去重。当前有 `data.managed_wiki_sources` 和工具内部命中页信息，公开 `data` 尚无统一页面计数，应在工具／适配层补齐；`found_kbs` 只是路由信息，不能据此计算命中页数。 | `找到 N 个 Wiki 页面`；明确成功且页面数为 0 时显示 `无匹配`。 |
| 阅读 Wiki | `read_page_count` 统计本次实际输出正文的页面，受管结果可结合 `data.managed_wiki_sources`；`truncated_slugs` 对应截断，`omitted_slugs` 对应未输出页面。适配层需保留页面的知识库身份，`ambiguous_slugs` 不能单独当作已读页数。 | 1 页为 `已读取页面`，多页为 `已读取 N 个页面`；有截断补 `，部分内容已省略`；有遗漏补 `，另有 M 个页面未读取`。不能将未输出页面算作已读。 |
| 分析表格 | `row_count = data.row_count`，缺失时取实际 `data.rows.length`。这是 SQL 返回行数，不是原表总行数或计算项数。 | `已完成分析，返回 N 条结果`；明确返回 0 行时显示 `已完成分析，无返回结果`。 |

通用显示规则：

1. `status=running` 不显示结果小字；末行本身表达正在执行。计数尚未返回、为空或无法确认时，不写 0，也不显示「无匹配」；成功但无数量时可用「已完成检索／已完成读取／已完成分析」。
2. 明确失败用动作对应的「检索失败／读取失败／分析失败」，根据归一化的 `error_code` 补简短可读原因。现有内部 `error` 需先转换，避免原样展示日志、SQL 或服务内部信息。`success=false` 不能映射为「无匹配」。
3. 部分成功保留已完成数量并说明明确的截断／遗漏；取消和超时只将尚未结束的步骤标为「已取消／已超时」，此前完成的步骤及其结果保留。结果未能确认的历史步骤显示「结果未确认」。
4. `stage.count` 在受管运行路径可能是累计工具步数，不能代替上述任何命中、读取或页面数量。原始 XML `output` 的解析和计数归一化放在工具／服务端适配层，前端不以正则猜测其含义。

#### 引用类型判定

前端从 `GET /api/des/v3/runs/{des_run_id}/knowledge/evidence?message_id=...` 读取证据。外层 `items[]` 按知识调用返回，每条记录的 `items[]` 才是用于展示的证据。以证据项的 `kind` 判定证据粒度，再以 `source.kind` 判定来源类型。同一次混合问答可以返回 RAG 和 Wiki 证据，需逐项判断。问答模式、阶段名称、标题和文件后缀仅用于各自的展示。 [DES 证据类型](../../../工业万悟/des/digital-employee-service/internal/knowledgev3/native/types_generated.go) · [证据接口组装](../../../工业万悟/des/digital-employee-service/internal/knowledgev3/engine/sources.go)

| 证据 | 判断条件 | 前端取字段 |
| --- | --- | --- |
| RAG 文档片段 | `item.kind === "hit"`，且 `item.source.kind === "document"` 并携带 `item.hit` | 标题取 `source.title`，片段取 `hit.text`，`hit.source_id` 对应 `source.id`。`source.locator.chunk_id`、`page_number` 和 `text_anchor` 可用于定位，按实际返回使用。每个命中片段保留独立证据身份。 |
| Wiki 页面 | `item.kind === "source"`，且 `item.source.kind === "wiki"`。对应的 `source.locator.source_type` 为 `"wiki"` | 标题取 `source.title`，页面身份取 `source.locator.wiki_page_id` 和 `wiki_slug`。页面级证据的 `hit` 为空，正文节选通过现有引用原文接口的 `body` 获取；悬停显示标题、所属知识库及正文节选；点击正文标签先打开本轮知识浮窗并定位 Wiki 卡片，点击「查看」再打开页面原文弹窗。 |
| 表格计算 | `item.kind === "calculation"` | 摘要取 `calculation.summary`，依赖的原表取 `calculation_sources[]`。文档样式可以复用，正文内容按计算摘要渲染。 |
| 其他来源 | 例如 `item.kind === "source"` 且 `source.kind === "document"`，或 `source.kind === "faq"` | 文档级来源展示文档信息；FAQ 按其类型和实际返回的正文展示。保留原证据粒度。 |

Wiki 预览的正式前端取值：确认 `access === "available"` 后，以 `evidence_id` 和 `source.id` 调用现有 `readKnowledgeCitationContent(runId, evidenceId, sourceId)`。该封装返回 `content` Blob；Wiki 响应为 JSON，解析其 `body` 和 `source`，确认来源身份后生成纯文字节选。悬停请求期间显示「正在加载页面内容」，失败或正文确实为空时再显示相应提示，不以缺少 `hit` 判断 Wiki 没有内容。切换引用时避免旧请求覆盖当前页面；当前会话可按调用、证据、来源及版本复用已读取内容，权限校验失败时清除内容。完整原文仍按 Markdown 展示。此流程可复用现有接口，无需新增 Wiki `hit.text` 字段。

正文编号与同一 `answer_message_id` 下证据项的 `final_citation_number` 匹配。编号为空的证据保留在「本轮引用知识」的全部及未引用列表中，不生成正文引用标签。仅使用 `access === "available"` 的来源元数据与内容渲染标签、悬停和原文入口。知识库名称通过 `source.resource` 中的知识库身份匹配已有知识库元数据。

正文同一处连续引用同一份 RAG 文档的多个片段时，以知识库资源身份和 `source.document_id`（或 `source.locator.document_id`）归并标签，保留各自的引用序号和 `evidence_id` 供悬停切换。点击正文引用时用证据身份定位本轮知识卡片；点击卡片或引用浮窗的「查看」时，用该证据的 `evidence_id` 和相应来源的 `source.id` 请求引用原文接口。Wiki 响应中的 `body` 按 Markdown 渲染。 [WeKnora 文档与片段字段](../../../工业万悟/weknora/internal/application/service/wanwu_resource_search.go#L185) · [WeKnora Wiki 页面字段](../../../工业万悟/weknora/internal/application/service/wanwu_resource_search.go#L326) · [DES 引用原文鉴权](../../../工业万悟/des/digital-employee-service/internal/knowledgev3/engine/sources.go#L429)
