# 对话区呈现改造 PRD（现有页面增量方案）

状态：已完成当前确认范围的纯本地演示；上游待定交互仍需确认
更新：2026-10-21
范围：`专家` 演示工程的现有专家对话页

## 1. 文档定位

本文回答**如何在现有对话页上分五步改造**，不是另一套独立页面，也不复制 Hermes 的事件协议。改造对象是当前 `src/demo/pages/Chat.vue`、对话演示状态及其样式；专家列表、任务卡片、工作空间和项目页面既有规则继续按 [experts_prd.md](./experts_prd.md) 执行。

设计依据是 `D:/CodingWorkSpace/PublicProjects/hermes-agent-main/docs/design/conversation-presentation.md` 的第 2 章与第 3 章：§2.1–§2.4 决定两阶段、P1–P9 模板、跨类别场景与展示基线；§3.1–§3.8 的各节“呈现字段与模板”和“场景示例”决定逐类内容的映射与验收。第 1、4 章用于核对事件身份、字段可用性和恢复边界，不把拟新增能力当成已有接口。该文档仍在编写；明确标为待定的交互不能直接视为最终产品决定。

本工程继续保持**纯演示模式**：业务数据和事件在浏览器本地模拟，不接入 Hermes、DES 或宿主 API。为了检验将来的呈现逻辑，本地事件可采用与 Hermes 相近的身份和状态字段，但不得向用户声称它们来自真实 Agent。现有对话页逐步替换，不再维护单独的模板原型路由。

## 2. 目标与不变量

### 2.1 用户要看清的三件事

1. **本轮说了什么**：用户输入和专家可见答复始终在对话阅读主线上。
2. **本轮正在做什么、结果如何**：工具、推理、委派和临时等待有不同的归属；完成、中断、失败不能共用“处理完成”。
3. **重新打开还能看见什么**：最终答复和可恢复的关键事实保持一致，不补造没有保存的逐帧过程。

### 2.2 贯穿五步的规则

- Session 是多轮对话，Turn 是一次提交引发的执行，Event 是本轮的增量或状态变化。`message.complete` 只收口**本轮**，不代表整个 Session、长期目标或后台任务完成。
- 一条事件不等于一条消息。同一文字段、工具调用或人工请求要按自身身份**原位更新**，不能因增量、进度或同文收口生成重复卡片。
- 回合状态 P7 放在**对话时间线的本轮顶部**，不恢复页面顶栏曾移除的“运行中”标签。
- 完整最终答复保持在主视图；过程可折叠。临时等待状态在结束后消失；错误原因独立于助手正文展示。
- 本地演示仅模拟能解释清楚的事件。没有真实来源的工具进度、产物、百分比、用时或历史活动不得为了填满界面而虚构。
- **计时只在本轮顶部汇总**：执行中展示本轮累计用时，结束后显示本轮总用时；活动项和工具行不展示各自计时。工具完成、失败可用文字或上下文说明，不使用单项末尾的 √／× 作为最终状态图标。
- 切换任务、停止生成和刷新页面时，旧回合不能串入新任务；显示状态须与保存下来的演示数据一致。

### 2.3 修订后的持续实施目标

在**现有** `Chat.vue` 中，按“数据语义 → 主线呈现 → 复杂过程 → 人工介入／结构化状态／结果异常 → 视觉与回归”五步，把第二章 P1–P9 和第三章八类信息的**呈现字段、处理规则及场景示例**落实为可演示、可验证的本地行为。每一步既检查第二章的模板位置与两阶段变化，也检查第三章对应字段的可见／不可见边界、身份关联、缺字段降级、去重、终态和历史。具体逐节目标与验收场景见第 8 章；不能只凭模板外观或少数关键词演示认定第三章已覆盖。

本目标不改变纯本地演示边界，不接入 Hermes/DES/宿主 API。上游标明待实现或待确认的能力，应记录为**演示适配、待确认或暂不承诺**，不得描述为既有后端合同。以用户本轮要求覆盖源文档的两处细节：**只在回合顶部显示本轮总用时，不展示任何活动单项耗时；工具项不以 √／× 表示最终状态**。除源文档明确规定的内容层次、状态和样式外，保留当前专家页风格。

## 3. 第二章模板如何落在现有页面

### 3.1 对话时间线

- **P1 主消息**：用户输入气泡与无气泡的专家文字。流式文字原位增长，终态文字校正同一段；同文 `interim` 不复制成另一条答复。
- **P7 回合状态**：本轮顶部表示处理中、已完成、已中断、处理失败或状态待核对；用时有可信起点才显示。执行中保持展开，结束后默认收起过程。
- **P2 过程详情**：中途说明及活动项的可展开文字。它是内容层，与 P4 活动组是包含关系或相邻过程段，不另造与 P4 重复的“处理卡”。
- **P4 活动组**：可见推理、工具执行、子代理／并行模型按逻辑活动聚合；同一次工具调用按 ID 更新一项，并行完成顺序不改变归属。
- 相邻处理活动之间没有实际呈现的助手中途文字或人工请求时，归入同一活动组。最终回复的流式文字在过程后独立展示，不因它到达于两个活动事件之间就切出空白分组；历史重开保持相同分组。
- **P3 临时活动行**：当前等待、整理上下文等短暂状态。新的有效进展或回合终态使其消失，历史中不保留虚构的 spinner。
- **P5 人工介入记录**：在时间线保留 Hermes 问题与用户选择／回答；提交后原位转只读，不回显密码和密钥值。
- **P8 结果与证据**：有可关联且可恢复的文件、清单等本轮结果时，放在最终答复之后；不从答复措辞猜测产物。
- **P9 异常提示**：本轮最后独立显示需要用户知道的错误、警告或阻断原因；安全地描述可用恢复动作，不倾倒原始对象或堆栈。

### 3.2 输入区上方

- **P6 输入区上方状态**：当前待处理的人工请求、一个大目标、一个执行计划和多条排队任务按实际数据出现。人工请求与 P5 使用同一 `request_id`，只提交一次；处理后撤下相应请求。状态快照原位更新，不反复新增对话消息。人工请求不覆盖其他状态。
- 大目标、执行计划、排队任务分别支持展开和收起，默认收起。大目标收起时可见名称与状态，展开后查看说明及阶段；执行计划收起时可见完成数量与当前或下一步骤，展开后区分待处理、进行中、已完成、已取消及父子任务；排队任务收起时可见数量和下一项，展开后按顺序查看多条任务及各自详情。折叠状态不改变数据或历史结果。
- 三类状态一般不会同时出现，但允许按实际快照独立并存。真实入队、执行顺序控制、打断与恢复规则仍待上游确认；本地演示仅展示固定队列快照，不将其描述为真实调度能力。

### 3.3 两阶段与历史

- **执行中**：P1 可增长；P7 显示处理中；P2／P4 记录真实模拟活动；P3 仅在当前等待时出现；P5／P6 可承载待回应请求。此时不能提前断言哪段 `delta` 是最终答复。
- **本轮已结束**：P7 严格按终态区分完成、中断、失败；P1 原位收口；P2／P4 默认折叠；P3 消失；P5 决定留作只读记录；有依据时再出现 P8 或 P9。
- **历史重新打开**：从已保存的本地消息及关键状态重建同一阅读结构；不回放旧动画，也不填造当时没有保存的活动项和耗时。短时实时事件与长期历史不是同一来源。

## 4. 五步增量修改计划

每一步都在现有 `/experts/:id/chat` 页面完成，可独立验收后再进入下一步；前一步通过后继续保留其行为。每步还须核对第 8 章对应的第三章字段规则与场景示例，不能只验 P1–P9 模板外观。下面的“本地事件”指演示数据，不表示真实 Hermes 协议已接入。

### 第一步：数据语义与演示事件

**目标**：让页面有明确的 Session、Turn、文字段、活动项、人工请求和终态，避免继续以“用户消息＋单条助手消息＋固定两步过程”承载所有情况。

- 在本地数据层定义回合身份、状态与顺序；工具项有调用 ID，人工请求有请求 ID。演示中的 `seq` 只用于本地排序和去重，不冒充真实 Hermes 事件序号。
- 让固定场景按事件语义驱动同一对象的开始、增量、完成、失败或中断；保留现有旧演示数据的读取或迁移路径。
- 处理刷新时遗留的“生成中”状态：没有仍在运行的本地计时器时进入可解释的中断／待核对状态，不无限显示忙碌。

**验收**：重复事件不会复制文字或工具项；两个同名并行工具按 ID 各自结算；切换任务、停止和刷新后不会串消息。此步主要改数据层，现有页面布局可暂时不动。

### 第二步：主线呈现（P1＋P7）

**目标**：先把用户输入、专家正文和单轮状态做对。

- 在现有时间线中按回合展示用户输入、回合顶部和专家正文；`delta` 原位增长，`complete.text` 校正同一条答复。
- 完成、中断、失败使用不同状态。删除固定的“4.7 秒”兜底；没有可信时长就不显示。
- 保留部分文字，但不能把中断或失败的部分输出标成成功结论；独立错误可关闭忙碌态。

**验收**：无工具的普通回复、部分输出后失败、用户停止、空 `complete.text` 都能正确收口；页面顶栏不出现重复运行标签。

### 第三步：执行过程（P2＋P3＋P4）

**目标**：把有时序的过程信息放进可阅读、可折叠的活动结构。

- `interim` 封口中途说明，与已流出的同文去重；必要时在过程区域保留与最终答复不同的说明。
- 活动组容纳可见推理、工具和委派；每个逻辑活动原位更新。运行中标题使用「正在推进 · 动作文字」，多个并行活动按开始顺序列出正在运行的动作，不显示工具参数，也不额外选择“焦点活动”；已结束的活动从运行中标题移除、原项仍可在组内查看。`tool.generating` 与普通 spinner 不计为正式工具项；无上报时不编造 `tool.progress` 或百分比。
- 临时等待单独呈现，遇到有效进展或终态即消失；回合结束后过程默认收起，最终答复保持可见。

**验收**：过程说明、工具、最终答复各只出现一次；并行工具和委派结果不串项，运行中标题随活动起止更新；缺少过程事件的回合仍能正常显示。具体工具名到中文动作的映射、缺身份字段时的降级规则待上游文档进一步明确。

### 第四步：人工介入、结果与异常（P5＋P6＋P8＋P9）

**目标**：把“需要用户操作”“本轮产物”和“本轮异常”与助手正文分开。

- 澄清和审批用同一请求身份驱动时间线记录与输入区上方的操作浮窗；提交后浮窗撤下、记录原位变只读。批准仅代表允许尝试，不代表后续工具已成功。
- Todo 与目标／循环／心跳分别按各自演示快照及版本规则更新 P6，不把每次快照新增为消息；不把轮次预算或触发次数画成业务完成率。
- P8 只展示有演示文件或结构化结果依据的内容；P9 只展示需告知用户的安全错误／警告，在最终答复和结果之后。

**验收**：重复提交和晚到回应不会改写其他请求；失败时部分正文、终态和错误原因各在正确位置；无产物时不显示空结果区。凭据输入、请求失效、多请求并存和完整审计恢复先按 §8.7 核对规则与安全边界；只能明确演示可安全模拟的路径，不宣称已有完整服务端恢复能力。

### 第五步：视觉细化与完整回归

**目标**：在数据和状态正确后，仅按上游文档已明确的要求细化现有对话页，而不是再做独立原型或整体换肤。

- 对照上游 §2.4 调整阅读顺序、折叠展开、长文本、代码块／表格、文件卡、窄屏与键盘操作；保持当前专家页和任务列表的已确认交互。
- 重点核对执行中、结束后、历史重开三个视图的层次；P7 是回合内状态，P6 始终属于输入区上方，不挤入消息流。
- 保留现有页面的基本色彩、容器和输入区风格；本轮只调整文档明确指定的消息层级、过程折叠、阅读顺序与必要的状态表达。参考用户提供的现有对话截图，不将其视为新增独立页面。
- 以固定模拟场景和浏览器检查做回归；纯排版参数保留在前端代码，不写成 PRD 的像素规则。

**验收**：下节场景全部通过，刷新和任务切换后阅读顺序及状态一致；不产生真实业务请求。

## 5. 回归场景与阶段门槛

- **基础答复**（第二步起）：有／无流式片段、空完成文字、正常完成，不重复输出。
- **停止与失败**（第二步起）：部分文字保留，状态分别为中断和失败；错误原因不混入助手正文。
- **过程交错**（第三步起）：`delta → interim → 并行工具 → complete`；同名工具按 ID 更新；无工具事件时页面可正常收口。
- **临时状态**（第三步起）：等待说明被新进展替换，回合结束与历史重开不保留旧 spinner。
- **人工介入**（第四步起）：澄清／审批请求与决定按同一 ID 关联，操作浮窗撤下后时间线仍可读。
- **结果与异常**（第四步起）：有真实演示依据才出结果；部分失败仍保留有用文字并给出独立异常提示。
- **跨状态**（第五步）：切任务、刷新、历史重开、上滚阅读和窄屏下内容不串位、不丢失最终答复；可访问操作仍可用。

## 6. 上游待定事项与本轮处理方式

1. **P6 浮窗并存及优先级**：上游尚未确定。本轮只展示明确的单请求与单状态场景；不设计隐藏队列的最终产品规则。
2. **手动展开状态跨阶段的保持方式**：先按上游 §2.4 的默认折叠规则实现；是否保留用户已展开的内容，待交互稿确认。
3. **历史过程的留存范围**：只显示当前演示数据真实保存的内容。长期过程审计、稳定跨刷新回合 ID 和完整请求恢复依赖上游补充，不用短时事件缓冲冒充历史库。
4. **通用工具多步骤进度**：普通自注册工具尚无通用保证。演示可展示“某个工具确实上报了进度”的专门场景，但正式接入前不得承诺所有工具都有进度条。
5. **结构化结果的来源映射**：文件、待办与可访问引用的具体字段由上游第 3 章继续细化；本轮 P8 只使用固定且能追溯的本地结果。
6. **执行中继续输入**：上游 §2.3 描述排队、转向、中断后排队及提交失败，不是单一的“继续发送”。现有演示页在运行中禁止发送；待上游明确本期采用的模式后再决定输入区与回合关联规则，不能把后端可能返回的几种结果同时当成本期必做。

## 8. 上游第二、三章逐节目标与场景验收

本章是 §2.3 持续目标的**详细验收清单**，而非 Hermes API 对接承诺。每节都要分别核对“该显示什么”“不该显示什么”“发生状态变化时更新哪个对象”，并以对应场景验证。第三章提到的单项 `duration_s`、`duration_seconds` 与本项目已确认规则冲突时，以**仅回合顶部总计时**为准；工具状态可保留在数据中供判断，不在活动行显示最终 √／×。

### 8.1 第二章：整体展示基线与跨类别协同

- **§2.1 两阶段**：运行中允许正文增量、过程活动、短暂等待和人工介入并存；回合结束由明确终态收口，最终答复留在主线，过程折叠，历史从已保存事实重建，不逐帧伪造直播。
- **§2.2 P1–P9**：P1 用户与专家文字；P2 中途说明／活动详情；P3 临时等待；P4 身份明确的逻辑活动组；P5 人工问答记录；P6 输入区上方的当前请求或状态；P7 本轮顶部状态和总用时；P8 有来源的本轮结果；P9 尾部独立异常。每个模板必须有明确的显示位置、开始／更新／收口条件和历史边界。
- **§2.3 跨类别场景**：核对 `delta → interim → 工具 → 最终答复`、人工回应后继续执行、断线去重与部分失败。执行中续输的“排队下一轮、转向当前轮、中断后排队、提交失败”是四种不同结果；现有演示页仍禁止运行中提交，后续只有上游明确采用模式时才增加对应交互，不把四种模式合成一个通用“继续发送”。
- **§2.4 阅读与折叠**：按真实时序放置回合顶部、活动组、临时行、人工气泡和最终正文；活动组与单项详情默认收起，执行中顶部不可折叠，结束后顶部默认收起。结果只在最终答复后，异常最后。长文本、代码和表格可读；历史无可信总时长时不补造。页面已有导航、任务区、输入区风格继续保留。

### 8.2 §3.1 助手可见文字：P1／P2／P7／P9

- **呈现字段**：用户原文和附件进入右侧 P1；`message.start` 只启动 P7，不生成空助手消息；`message.delta.text` 原位追加一段 Markdown 正文；`message.interim.text` 封口中途段，同文不复制；`message.complete.text` 原位确认或修正最终段，空串不抹除有用片段。`status` 只驱动顶部完成／中断／失败，安全的 `error/warning/billing/failure_reason/error_surface` 按同源合并进 P9，不作为助手答复。`already_streamed/seq/partial/recoverable/持久 ID` 只参与关联判断，不显示原值。
- **场景验收**：流式同文收口；已流与未流的 `interim`；中途段与最终段同文、前缀连续及真正不同三种情况；无 `delta` 直接 `complete`；空完成文字、部分失败和错误兜底文字。最后一种不能把 `Error: …` 当正常结论。附件只展示实际提交的本地引用。

### 8.3 §3.2 推理与等待提示：P4／P2／P3

- **呈现字段**：只有获准可见的 `reasoning.delta.text` 合并为一个默认折叠的“思考”活动及详情，不宣称完整内部推理；`thinking.delta.text` 是 P3 当前等待，下一有效进展或终态清除。`reasoning.available.text` 可能是正文预览，`message.complete.reasoning` 可能只是末段推理，两者不据此新建或补齐思考项。
- **场景验收**：多段推理增量仍只占一项，最终答复独立；只有等待时无思考项且历史无 spinner；只有一次性预览时只显示可信的最终正文。重新打开仅恢复确实保存且获准展示的推理文字。

### 8.4 §3.3 工具执行：P4／P2，条件性 P6／P8／P9

- **呈现字段**：`tool.generating` 不建项；`tool.start` 按稳定 `tool_id` 建项，工具名映射中文动作，未知插件／MCP 用“调用外部工具 {名称}”。组标题只列正在运行的动作；组内标题后缀只占一个位置，优先级为**可读进度 ＞ 指定工具的安全参数摘要 ＞ 无后缀**。参数、网址、命令、代码按工具类型脱敏和截断；只有实际返回的可读内容、diff 或可访问文件才进入展开详情或 P8。`tool.complete` 更新原项，不将动作改成完成时态；单个工具失败不直接宣判父回合失败。风险提示需要用户知道时才进 P9。
- **场景验收**：读取文件的安全路径摘要；有真实进度时原位替换参数摘要，后续进度不堆列表；仅确认成功的写入无空出参；无 stdout 的命令无“无输出”占位；同名并行工具按 ID 分别结算；没有 progress 也是正常路径；漏收 start 的 complete 只补建同一项。演示数据没有真实上报时不得制造百分比或工具结果。工具详情可说明状态，但**不显示单项耗时和最终 √／× 图标**。

### 8.5 §3.4 子代理与并行模型：P4／P2，条件性 P8

- **呈现字段**：有原生子代理事件时，`delegate_task` 不另造重复工具项；每个子任务按自身身份和简短目标更新一项，最近活动原位更新，`complete.status` 决定该子项状态，不由摘要文字猜测成功。只有真实可打开的 `child_session_id` 才给子会话入口，只有可访问文件才进 P8。MoA 是一项“并行模型”活动：真实参考完成数只是参考模型计数，意见按来源进入展开详情，聚合阶段原位替换进度；父助手答复仍由 `message.*` 输出。
- **场景验收**：两项同名或不同目标的子任务 B 先于 A 完成；子任务最近活动和结果摘要不变成父答复；后台委派晚于父回合结束时只更新子项；MoA 的多条参考意见不变成多个子代理或多份最终答复。身份缺失时使用安全降级，不按目标文字盲目合并。

### 8.6 §3.5 阶段与过程状态：P3／P9

- **呈现字段**：`status.update(compacting)` 映射固定的临时文案，`compacted` 清除；只有白名单 lifecycle 阶段可进 P3。确需用户知晓的 `warn` 以安全文案进入 P9 并与同源终态警告去重。`goal/loop/heartbeat` 自由文本只触发结构化快照刷新，`process` 只触发后台进程状态刷新；未知 kind、空 text 和内部关联字段不生成活动、百分比或成功结论。
- **场景验收**：压缩上下文提示出现后消失；完成后晚到的目标通知只更新 P6 快照、不改答复；后台进程通知不在时间线新增过程行。状态通知不能结算工具、子代理或整个回合。

### 8.7 §3.6 人工介入：P5／P6

- **呈现字段**：同一 `request_id` 驱动右侧只读问答记录和输入区上方唯一操作入口。澄清按实际题目、`qid`、单／多选或自由输入收集；审批只列后端允许的选择，批准仅允许继续尝试。sudo／secret 只保留“已安全提交”等脱敏决定，绝不保存、复制或回显密码／密钥。MCP 设置决定与后续 `setup_mcp` 工具结果分开；失效只更新匹配的待处理请求，不当成用户拒绝。待处理快照只恢复已被接收的答案及仍有效的选择。
- **场景验收**：澄清提交被接收后 P6 撤下、P5 原位记录且后续答复独立；审批获准但后续工具失败；凭据不回显；超时／断线与旧请求晚到回应不覆盖新请求。多题、sudo／secret、MCP 设置和并行请求在纯演示中应先以明确的本地场景验证，缺真实恢复合同的路径不得伪装为后端已支持。

### 8.8 §3.7 结构化任务状态：P6，条件性 P8

- **呈现字段**：Todo 是带数字 `revision` 的完整快照，按真实 `id/content/status/parent` 原位替换；旧版本被拒、空数组表示清空，取消项不计入完成分母。目标／循环／心跳来自另一份 `session.control.update` 快照，内部指纹与 Todo 数字版本不混用；目标 `turns_used/max_turns` 是轮次预算，不画成业务完成率。循环触发次数和心跳检查次数也不等于完成进度。P6 表示当前会话状态；只有另有**绑定本回合且可恢复**的结果快照时，才在 P8 展示本轮 Todo 等交付。
- **场景验收**：Todo 版本 3 后拒绝版本 2、再由新版本空数组清空；回合完成后目标仍 active 且晚到快照只更新 P6；真实等待截止时间才显示目标等待；循环与心跳同时存在时分开表达。不能从旧工具行或 `status.update.text` 推断当前正在执行。
- **执行计划交互**：同一快照展开、收起前后的完成数量一致；父子任务与取消状态可辨识；切换会话后展示目标会话的当前快照，不复用上一会话的任务内容。

### 8.9 §3.8 回合结果与故障：P7／P1／P8／P9

- **呈现字段**：`message.complete.status` 只收口本轮；`text` 按 §3.1 原位收口；安全的错误、警告、账单阻断和恢复说明按同一故障合并为一条 P9。独立错误只有能关联本轮时才进入该回合，必要时关闭忙碌态，但不能凭它伪造成功／失败终态。`session.info.turn_started_at` 只用于 P7 顶部总计时；`partial/recoverable/running=false` 是判断线索，不直接生成结论；会话累计 usage 不插入回合。`notification.show/clear` 走页面通知位置，不默认复制到 P9。
- **场景验收**：正常完成；部分文字后失败且 P9 在最后；终态丢失时先恢复核对，仍不明才标“运行异常”；账户通知按 key 更新清除而不生成消息。未知恢复能力不能提供虚假的“重试成功”操作。

### 8.10 五步实施与完成判定

1. **数据语义**：先覆盖 §2.1、§2.3 与 §3.1–§3.8 所需的回合／对象身份、序号、快照版本和历史来源；写明哪些只是本地模拟字段。
2. **主线呈现**：完成 §3.1 与 §3.8 的 P1／P7 基础收口、部分失败及顶部总计时；不能以固定回复案例替代空文字和异常路径。
3. **复杂过程**：完成 §3.2–§3.5 的推理、临时状态、工具、子代理和 MoA，逐项检验 ID 配对、进度后缀优先级、灰色活动与默认折叠。
4. **人工与状态／结果**：完成 §3.6–§3.8 的请求生命周期、Todo／控制快照、P8 来源和 P9 去重；将尚未定稿的并发和恢复能力明确标注，不臆造正式服务端行为。
5. **视觉和回归**：只细化第二章明确的呈现样式；按本章场景逐项进行状态测试、浏览器阅读顺序检查、刷新与切任务验证、离线请求检查和生产构建。最终判定需要逐条证据，不以目前已通过的部分用例替代八类信息的全覆盖。
