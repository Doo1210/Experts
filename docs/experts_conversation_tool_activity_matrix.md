## 1. 通用取数与呈现规则

| 层级／事件 | 运行中的通用规则 | 可用字段或能力 |
| --- | --- | --- |
| 建立活动 | 收到带稳定调用身份的 `tool.start` 后建立一项；同名并行调用按各自 ID 保留独立活动行。`tool.generating` 不建行。 | `tool.start.tool_id/name/args`；`session_id + seq` 用于事件归属和顺序。 |
| 事件可见性 | 只呈现当前网关实际投递的工具事件；缺少 `tool.start` 时不预造“正在执行”的活动行。 | `tool.start/complete` 是否发出受工具类型和网关显示配置影响，进度事件也非通用必有。 |
| 活动组标题 | 通常为 `正在推进：{动作} · {安全对象}`，对象优先于进度。命令、代码与后台进程只显示动作，不带命令、代码或进程参数；多项进行中活动按开始顺序显示前两项，其余显示数量。 | 动作由 `tool.start.name/args.action/background` 映射；其他工具的对象从允许展示的 `args` 字段提取。 |
| 活动行 | 依次显示动作、安全对象、最新进展／异常状态；三者以字重、颜色和间距区分，不与组标题使用相同的圆点串接。对象保持稳定，进展在末尾原位更新；缺失字段不占位。 | `tool.start.name/args`；同一 `tool_id` 的 `tool.progress.preview/current/total/unit`，若实际提供。 |
| 活动详情 | 在所属活动行内展开，明确与该行对应。成功工具只展示必要的安全入参与真实输出；只有失败、拒绝、中断或状态待核对才另写状态。无额外可读内容时不出现展开入口。 | `tool.start.args`、可关联的 `tool.progress` 与 `tool.complete.result`。通用 `context` 仅作辅助。 |
| 进度可用性 | `tool.progress` 可为零条或多条；可读 `preview` 优先于数值进度。只有 `current/total` 均真实有效且 `0 ≤ current ≤ total` 时才显示比例。每次进度更新原活动，不增加活动行。 | 当前 Hermes 普通注册工具尚无统一的带 `tool_id` 逐步进度上报；原型的专项演示进度均为本地模拟，不能当作真实能力。 |
| 安全与缺失 | 网址去账号、查询参数及片段；路径优先工作区相对路径或文件名；命令、代码和搜索词需脱敏。无法安全概括对象时仅显示动作，不展示原始 `args`。 | 产品侧白名单映射；现有原型的 `toolAction()`、`toolArgumentSummary()`、`toolInputText()` 仅供参考。 |
| 视觉与用时边界 | 活动组标题与活动行从同一左边界开始，不额外缩进；活动行保留前置中性圆点，详情框左边界与活动行名称对齐。圆点不承担运行状态动画，也不使用蓝色竖线。确实运行中的活动组标题与活动行文字以低强度灰色扫光从左到右循环；等待启动、完成和异常状态保持静态。悬停／聚焦时暂停，系统要求减少动态效果时静态显示。组标题以“正在推进：”或“处理经过：”引出摘要。本表不为每项活动显示计时，也不增加完成／失败的勾叉图标。 | 回合总用时仍归回合状态行；工具 `duration_s` 不进入运行中标题。 |

表格以下各行均描述**一项活动正在运行**的样式；活动组有多项并行活动时，分别套用各行规则，不将不同工具的进度合成整体百分比。详情与最终答复、本轮产物和会话状态卡承担不同职责，不能重复堆放同一份内容。

**真实进度接入合同（Hermes 待补能力）**：同一次工具调用的每条进度须携带稳定 `tool_id`，由网关附上 `session_id + seq`；内容可为经过脱敏、限长的 `preview`，或真实 `current/total/unit`。进度可为零条；高频上报应节流，晚于可信终态的进度不再改写活动。当前普通注册工具的进度回调尚未统一投射为这一事件，因此没有该事件时只展示动作与安全对象。

下表活动行中的 `·` 仅用于标明动作、对象和进展的字段顺序；原型的组内活动行通过文字层级区分这些字段，不显示圆点分隔。

## 8. 通用终态与历史规则

`tool.complete` 只结算所属调用。活动组在回合结束后显示“处理经过：{活动名称}”，不带对象、进展和状态；活动行仍保留安全对象，必要时追加文字终态。单项工具失败、被拒绝或中断不直接决定整个回合的终态。

| 事件与依据 | 工具活动终态 | 展示及降级 |
| --- | --- | --- |
| 有 `tool.complete`，且结果没有失败依据 | 已完成 | 活动行保留动作和对象；详情只展示真实返回或差异。`verified: true`、空标准输出等确认信息不生成虚假的出参区。 |
| `event.error`、明确失败状态、结果中的 `success:false`／`ok:false`／`error`，或终端非零退出码 | 未完成 | 先排除有明确阻断／取消语义的结果，再把其余失败归为“未完成”；详情给出脱敏原因。工具失败不自动决定回合终态。 |
| 工具结果中的 `status=blocked/denied/rejected` | 未获授权 | 从 `tool.complete.result.status` 等权威结果识别，不依赖网关通用的顶层 `tool.complete.status`；只说明本次调用未获授权。`status=pending_approval` 是等待人工决定，交给审批请求承载，不能当成阻断。执行前拦截可能没有可见完成事件。 |
| 工具结果中的 `status=cancelled/canceled/interrupted` | 已中断 | 从可信结果识别并只结算该项工具；真实用户中断可能同时中断父回合，不承诺父回合必然继续。未实际执行的取消结果不展示 `exit_code=-1` 为命令退出码。 |
| 回合结束、刷新恢复时仍缺少可信 `tool.complete`；写入类仅返回 `verified:false` | 状态待核对 | 清除过时的运行进度，不把“已处理 N/N”当作成功依据；只有补收到可关联的可信终态才能改写本项状态。 |
| 漏收 `tool.start`，但收到带稳定 `tool_id` 的 `tool.complete` | 按完成事件实际结果结算 | 只补建一条原工具活动，开始时间或中途进度保持未知，不回填想象出的步骤。 |

**历史最小记录**：按会话与回合保存调用 ID、开始和结束序号、工具名、产品动作、安全对象、终态、最后可信进展、经脱敏的必要入参／结果摘要，以及真实产物引用。原始 `args`、`result`、`context` 和 verbose 文本不作为活动记录直接持久化。当前本地原型可恢复这些已保存字段；Hermes 真实历史若要同样还原，需要服务端持久化该投影或可靠事件日志，不能从最终消息反推工具过程。

## 9. 高频结果类型与归属

| 结果类型 | 活动详情 | 其他归属与限制 |
| --- | --- | --- |
| 检索命中 | 按实际返回条目显示标题与脱敏来源；没有结果时不伪造列表。 | 结果网址须通过链接安全校验，不能把未核验的原始 URL 直接当作可点击入口。 |
| 命令与代码输出 | 非空标准输出和错误输出分开；非零退出码属于该项工具的失败依据。 | 不把命令输出当作助手最终回复；结果过长时限长并说明截断。 |
| 文件修改差异 | 仅在真实 `inline_diff` 存在时显示差异，不用完成事件伪造 diff。 | 可打开的生成文件另归本轮产出；输入文件不因被读取就变成产出。 |
| 新建或修改文件，以及已启用外部 MCP 的可访问产物 | 工具详情保留单次执行依据及实际 diff，不重复堆放同一份产物。 | 只有经过访问校验的 `result.add.fileId`、操作类型和可恢复的版本身份才进入本轮产出；按本回合文件身份归并，记录 `sourceToolId`。`result.add` 可在工具确认保存时到达，但产出卡片须等本回合最终回复收口后才展示。修改文件的整轮差异须另有可信来源，不能简单拼接单次 diff；原始路径／URL 不足以生成预览或下载入口。 |

活动组展开列表有最大可视高度；用户停留在底部时跟随新增活动，主动上滚查看旧详情时保持位置。完成后的“处理经过”仅列按首次出现顺序去重的活动名称；活动行仍可查看安全对象和异常终态。

## 10. 活动详情逐类开关与内容

**统一外壳、按内容选组件**：所有详情沿用同一所属活动行容器；内部按实际内容使用简短说明、结果列表、代码／输出、文件差异。生成文件和媒体的可打开入口归本轮结果，不另造一张相同产物卡。只有活动行之外还存在经过核验、脱敏、限长的有用信息时才给展开箭头。异常状态已在行内说明，若没有更多安全原因，也不打开仅重复状态的空详情。下面的“可展开”均以实际字段存在为前提，不表示所有调用必有详情。

本节仅列本期保留工具的详情规则。不开放工具的旧映射移至 §12，不参与新会话验收。

| 工具或类别 | 有条件展示的主要内容 | 适合的内部组件 | 不提供详情或不展示的内容 |
| --- | --- | --- | --- |

| 外部 MCP 工具 | 实际调用的安全请求参数与经整理的文本或结构化结果；异常原因归返回结果。 | “请求参数”“返回结果”两块，结构化内容用限长代码区。 | 不增加“调用工具”字段；不显示凭据、原始多媒体数据、资源缓存路径或未经整理的长日志。两块都为空时不展开。 |

**原型覆盖**：目前以 `toolInputText()` 决定额外安全参数、`toolOutputSections()` 决定结果组件，`hasToolDetail()` 决定是否可展开。专项演示仍含 §12 的旧场景，但不作为本期验收；真实 Hermes 接入须逐个核对已开放工具的 schema 和访问权限。

## 11. 排除与后续补充

| 场景 | 处理方式 | 依据 |
| --- | --- | --- |
| `tool.generating` | 不建立活动；等待稳定 `tool.start.tool_id`。 | 早期信号没有稳定调用身份。 |
| `clarify` | 归人工介入请求及回答，不再建立重复工具活动。 | `clarify.request` 与 `request_id`。 |
| `tool.output_risk` | 专门展示场景本期不开放；不把风险对象塞进普通工具进展或返回结果，也不将其自动视为工具失败。 | 原型演示见[演示触发词 §7.5](./conversation_demo_triggers.md#75-工具输出风险提示)；后续版本再确定提示位置。 |

### 研发核对点

1. 一项工具用 `tool_id` 关联 `start/progress/complete`；`session_id + seq` 负责事件排序和去重，不能以工具名合并同名并行调用。
2. 对象摘要要为每个已知工具建立白名单；组标题优先保留对象，行内再增加最新进展。当前原型的 [工具映射函数](../src/demo/conversation-tools.js) 仅是演示参考，不是所有 Hermes 工具 schema 的完整合同。
3. `tool.progress` 不保证存在。缺失时保留动作与安全对象；运行中不推断总量、完成率、输出或成功状态。
4. 参数、网址、路径、命令、代码及外部平台标识均先脱敏再截断。未知工具的原始 `args` 不直接进入标题或详情。
5. `tool.complete.result` 没有统一结构，先识别工具类别与明确的失败依据；后台进程的运行状态不等于 `process_manage` 本次调用的执行状态。
6. Hermes 的工具生命周期投递受 `display.tool_progress` 等配置影响；若产品要求完整历史，必须确认实际投递与服务端持久化能力。

## 12. 本期不开放

本期“不开放”指专家管理页不提供这些工具的启用入口，新建专家默认关闭，新的专家会话也不向模型提供对应工具 schema；仅在演示脚本或旧历史记录中保留安全的展示资料，不将旧活动视为仍可调用。工具集开关应在会话实际使用的 Hermes 配置中生效，不能只隐藏前端卡片。

另有一项**展示场景**本期不开放：`tool.output_risk` 的专门提示及“演示工具：输出风险”触发词不作为新会话验收内容。这不要求关闭 `web_search`、`web_extract`，也不影响 Hermes 的内部风险检测；风险事件不是工具执行终态。

- **外部记忆提供方与工具**：`memory.provider` 对应的 Honcho、Hindsight、Supermemory 等提供方本期不接入；不向新会话提供 `honcho_*`、`hindsight_*`、`supermemory_*` 等检索、保留或档案工具，也不展示其自动预取结果。Hermes 内置 `memory` 的增删改仍按第 7 节开放，不能因名称相近一并关闭。

- **外部平台与需单独授权的服务**：`x_search`、`spotify`、`a2a`、`homeassistant`（`ha_*`）、`discord`、`discord_admin`、`feishu_doc`／`feishu_drive`、`yuanbao`（`yb_*`）。本期不做对应的平台连接、账号授权或跨代理通信。
- **浏览器、电脑与桌面操作**：`browser`（`browser_*`）、`computer_use`、`desktop_ui`（含 `read_terminal`、`close_terminal`、`setup_mcp` 等）及 `project`（`desktop_project`）。产品自己的工作空间和 MCP 管理页继续使用各自业务接口，不通过这些模型工具实现。
- **图片、视频与语音工具**：`vision`（`vision_analyze`）、`video`（`video_analyze`）、`image_gen`、`video_gen`、`tts`；语音转文字 `stt` 是独立配置能力，同样不在本期开放。本轮上传图片仍可作为资料保存，不表示专家可以调用图片分析工具。
- **其他 Hermes 内置能力**：`cronjob`（`cronjob_manage`）、`kanban`（`kanban_*`）、`session_search`、`delegation`（`delegate_task`）、`todo`（`todo_list`）。定时触发由产品事件中心负责；产品的项目／任务对象不依赖模型直接调用 Hermes 看板工具。历史会话搜索、子代理派发及待办清单不参与本期新会话。

`web_search`、`web_extract` 本期保留。Hermes 可以选择免密服务提供方，但是否可调用仍取决于服务可用性与专家实际配置；不把“没有 API Key”直接解释为工具不可用。`code_execution`、`process_manage` 也继续保留。`clarify`、技能工具和按专家开关启用的 `memory` 维持原有功能归属；外部 MCP 服务只有在该专家明确配置并启用后才暴露其工具。本期待办快照、长期目标、排队任务、循环、心跳和账户通知场景均不开放；其旧原型触发词见[演示触发词 §7.4](./conversation_demo_triggers.md#74-当前会话状态与待办结果)。文件产出仍按 §9 实现。

### 12.2 旧详情开关与归属（本期不验收）

- `session_search` 仅在有可访问的会话摘要或定位信息时展开；`x_search` 仅在有真实命中与脱敏来源时展开。只有查询词时都不显示空详情。
