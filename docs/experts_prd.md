## 1. 专家

### 1.1 专家列表页

页面定位：展示「我的专家」，支持搜索、创建专家、从专家卡片进入管理页或发起该专家的对话任务。页面可切换到「项目」「专家模板」，切换后展示各自的列表和操作。

1023 已明确的跨页规则：

- 「我的专家」提供专家搜索和「新建专家」，搜索匹配名称、简介和标签；本页不提供「新建项目」。专家卡片「更多」只提供「发布为模板」「删除」，删除前二次确认；资料修改在专家管理页完成，不从卡片菜单打开编辑弹窗。
- 列表中的专家名称、简介和标签用于展示与检索，**不会自动写入 `SOUL.md`**，也不会替代岗位职责。岗位说明在专家管理页单独编辑（[prd.md §3.1](../../数字员工/docs/design/1023/prd.md#31-用户怎么理解)）。
- 从列表发起新的对话任务时，先进入尚未创建 session 的默认对话区；首次发送时才创建 session。默认工作目录为该专家的工作空间根；若用户在发送前选择已有子目录，则以所选目录创建 session，并显式传入 cwd，不自动建立 `tasks/<session-id>/`（[prd.md §5.6.3](../../数字员工/docs/design/1023/prd.md#563-新建对话)）。
- 新建专家时初始化自己的空工作空间，并预建 `消息渠道/`、`自主任务/`；不预建 `定时任务/` 或 `inputs/outputs/tmp`。从零创建且岗位说明未填写时，只在管理页的工作规范编辑缓冲预填默认句，保存前不写盘。
- 专家卡片可同时展示多个已接入消息渠道的图标；无渠道时显示未接入，图标悬停可识别平台。基本信息与新建专家弹窗保留头像选择，但头像选项上方不显示「预置头像」字样。

### 1.2 专家管理页

页面定位：管理一个专家的资料与能力。截图 2 是早期页面参考；当前原型的能力区已使用**技能、工具、MCP**三个独立 Tab。1023 在现有 Tab 上做增量，主要涉及**岗位说明、工作空间、任务、记忆、技能、工具、MCP、消息渠道**；顶部名称、简介、标签仍是专家列表资料。原型中的本地 store、模拟连通结果和示例文件只用于验证页面交互，不能视为服务端能力已经完成。

**共用功能规则**：专家级预置问题、记忆和主动学习技能各有独立开关；侧栏「任务」不显示数量角标。技能、工具和 MCP 的详情可查看对象名称、基本信息与启停状态，启停操作在列表卡片执行。只有打开详情这一项附加操作的卡片不提供 `⋯` 菜单。

#### 1.2.1 岗位说明 Tab

对应 [prd.md §3](../../数字员工/docs/design/1023/prd.md#3-岗位说明设计与实现)，覆盖现有「人设」Tab。

- Tab 改名为「岗位说明」，下设**岗位职责、作业流程、工作规范**三个子 Tab。编辑 Markdown 源码，不提供工具栏和实时预览。
- 三段只用于界面编辑。标题区的保存针对**一份** `SOUL.md`；继续使用 `GET/PUT /api/profiles/{name}/soul`，不拆文件或接口。编辑区不提供导入、导出。
- 三段可以全空。保存全空时保留内容为空的文件；新会话使用 Hermes 默认人格，不按专家名称生成职责。与 Hermes 默认 `SOUL.md` 一致的自动种入内容，在界面视为未填写。
- 从零创建且磁盘未填写时，只在**工作规范的未保存缓冲**预填工作目录规则；复制专家不额外预填。页面不提供「使用模板」按钮。
- 保存时按职责、流程、规范顺序拼成一篇 Markdown。拼装结果超过 **20000 字符**时禁止保存。
- 保存后仅新会话生效；若该专家有运行中会话，成功提示说明它们仍使用旧岗位说明。

**预置问题（1023 新增）**

- 原「人设」Tab 改名后，预置问题配置仍放在**岗位说明 Tab**，显示已配置条数、启用状态和配置入口。开启时可进入配置弹窗，维护该专家的问题列表。问题是对话输入辅助文案，**不写进 `SOUL.md`、不注入模型提示词**，保存后即可在该专家对话页使用。
- 预置问题支持添加、删除、拖拽排序。开启时至少保存一条非空问题，最多 20 条，每条最多 200 字符。保存前去首尾空白并去重；关闭开关保留已配置内容，再开启可继续使用。
- 专家对话页在开关开启且列表非空时显示「预置问题」。点击某条只把文字填入输入框，用户仍可编辑并自行发送，**不自动提交**。现有输入草稿的覆盖方式与示例问题的默认来源，见附录 C 待确认项。

#### 1.2.2 工作空间 Tab

对应 [prd.md §5](../../数字员工/docs/design/1023/prd.md#5-工作空间与工作目录设计与实现)。

- 工作空间属于专家，根路径来自该 profile 的 `terminal.cwd`。文件树展示整棵工作空间，支持更改根路径、新建文件夹、上传文件及浏览文件。
- 从零创建专家时，工作空间默认预建 `消息渠道/`、`自主任务/` 两个顶层目录。`自主任务/` 统一承载事件中心 Timer、WebHook、Pulsar、Kafka、MQTT 等触发的专家动作产物；不按触发源另建「定时任务」目录。复制专家时工作空间根仍重置为新专家自己的目录，不沿用源专家的绝对路径。
- 消息渠道群聊目录按「平台／`chat_id` 聊天／`session_key` 会话范围／`session_id` 会话段」组织；单聊不建范围层，段直接位于聊天目录下。聊天卡只打开聊天层，当前段是 agent 的 cwd。聊天、人改名不移动目录，收到的附件从 Hermes 缓存持久复制到当前段的 `收到文件/`。具体命名、文件索引和重置规则见 [prd.md §16](../../数字员工/docs/design/1023/prd.md#16-消息渠道聊天与工作空间)。
- 更改工作空间根只影响新对话的默认 cwd、新自主任务运行的默认目录和文件树根；已有对话及已有运行记录的 cwd 不自动迁移。界面须说明这一点，并对落在新根之外的旧 cwd 给出提示。
- 文件与文件夹操作列直接展示「重命名」「删除」，不再收进更多菜单；普通文件仍有预览、下载。沿用已有命名校验与删除确认。
- 文件与文件夹支持复选、多选及「全选当前列表」，选中后显示「删除 n」「下载 ZIP」。批量下载将所选文件和文件夹递归打包成一个 ZIP，保留相对目录和空文件夹；父目录及其子项同时选中时只打包一次。下载不改变选择或源文件；工作空间根不可选、不可删。
- 批量删除前二次确认文件和文件夹数量。若范围含某条任务的当前工作目录，提示删除后任务 cwd 不会自动改变。仅删除解析后仍在根内的路径，拒绝指向根外的符号链接；单项失败不影响其它项，结束后报告成功／失败数并保留失败项勾选。删除文件不改任何 session cwd，也不删对话记录（[prd.md §5.5.4](../../数字员工/docs/design/1023/prd.md#554-多选删除与打包下载文件和文件夹)）。
- 本 Tab 管理专家文件树，**不直接修改某条对话的工作目录**；对话的 cwd 在专家对话任务页切换。

#### 1.2.3 任务 Tab

任务 Tab 三个入口标为**平台对话｜消息渠道对话｜自主任务（事件中心）**，页面说明为「查看平台对话，消息渠道对话以及事件中心自主任务的记录」。没有独立「定时」分段或定时任务创建入口。Timer 是事件中心的一种触发源，命中专家动作后与其他触发源一样进入自主任务。人工对话 session、消息渠道的平台聊天聚合、事件中心专家动作及其执行记录是不同对象，不可只靠一个 `status` 混排；对话归档规则见 [prd.md §12](../../数字员工/docs/design/1023/prd.md#12-任务归档)。

**平台对话段**

- 操作栏统计显示「x 个对话任务 · x 个运行中」，分别取未归档平台对话任务总数与其中运行中数量，不显示已就绪数量；列表中的已就绪状态与状态筛选仍保留。
- 只列人工对话 session，排除 `source=cron`、消息渠道平台 source 与 `source=event_center`。未归档默认表的状态筛选只有**全部、进行中、已就绪**；已归档通过状态筛选旁独立的「归档任务 n」按钮打开弹窗查看。**恢复已归档对话任务只能在此弹窗执行**。
- 列表展示**任务、状态、当前工作目录、最近活跃、操作**。任务名称与 ID 同属任务信息，ID 支持复制完整值，复制按钮须有可访问名称；状态为运行中或已就绪；工作目录可跳转，最近活跃显示到分钟（`YYYY-MM-DD HH:mm`）。
- 未归档行的操作直接显示「打开」「编辑名称」，`⋯` 仅提供归档、删除。归档任务弹窗中的 `⋯` 仍提供编辑名称、恢复、删除。归档使用 session 的 `archived` 软标记，保留消息和工作目录文件；删除仍是硬删并二次确认。
- 从归档任务弹窗打开任务可查看历史并继续发消息，但它仍不出现在对话页右侧列表。归档不等于看板卡归档或自主任务的启停。

**消息渠道对话段（1023 新增）**

- 本模块只读展示 **Hermes 实际接收并处理的对话**，不等同于平台中的完整聊天记录。一张卡片代表一个聊天位置，按 Profile、渠道、平台作用域和 `chat_id` 归组；同群不同成员的会话范围归入同一张卡。`chat_id` 不可脱离 Profile 与渠道当作全局唯一 ID。卡片提供聊天名称、渠道、群聊／单聊、最近处理时间、`chat_id` 和聊天目录入口；点击卡片打开对话记录详情，目录入口独立打开聊天工作空间。不显示 session 数量。仅配置或连接渠道不产生聊天卡，`/new`、`/reset` 也不增加卡片。
- 搜索聊天名称或 `chat_id`，并按聊天类型、渠道筛选。**对话任务数**为当前筛选结果中的卡片数；**运行中数**为其中至少一个 Hermes turn 正在执行的卡片数，同群多个 turn 仍只计一张卡。现有 `is_active` 只表示近期活跃且未结束，不能当作运行中。部分聊天的运行状态无法确认时，统计仍只显示对话任务数与已确认的运行中数，不附加未知状态数量；全部聊天的运行状态均无法确认时显示「状态未知」，不推断为 0。已有历史仍可查看。聚合、筛选和统计在正式接入时由服务端完成。
- 群聊详情按成员查看**会话范围**，每个范围展示 `session_key` 的可识别摘要，支持查看与复制完整值、打开其工作目录。本期演示不展示群聊会话策略、共享范围或策略切换历史；未来规则见附录 F。**单聊不建立会话范围，产品记录中的 `session_key` 为 `null`，直接展示会话段。**会话段中当前段始终排在最前；每段展示 `session_id` 的可识别摘要和开始时间，仅当前段显示「当前」标签，并支持查看与复制完整值、打开目录。群聊的 `session_key` 是成员路由范围，`session_id` 是具体 transcript；同一范围执行 `/new` 后 key 不变而 ID 更新。
- 会话记录只展示选中的 `session_id`，按数据库消息行 `id` 排序，不按可能回退的时间戳排序。记录展示逐消息发送者、时间、用户输入、专家回复与附件；内部通知按时间线展示，工具调用默认折叠。段首可显示经证实的 `/new` 或 `/reset` 分界；只有 `end_reason=session_reset` 而无原始指令证据时显示「开始新会话」，不能推断成 `/new`。压缩及压缩 continuation 仍属原用户可见会话，不画成重置。
- Hermes 读取基础为 `sessions` 的来源、Profile、路由键、聊天／线程 ID、显示名、起止时间、父 session、结束原因与 cwd，`gateway_routing` 的**当前** key→ID 指向，以及 `messages` 的行 ID、角色、正文、显示元数据、工具调用和平台消息 ID。会话与消息现有接口可复用部分读取能力，但列表按 session 分页，无法直接提供聊天卡片聚合。
- 正式接入需要保存消息发送者及已证实的命令事件、聊天／成员范围／会话段目录与附件的持久映射。`/resume` 可能重绑路由，历史不可只靠当前 `sessions.session_key` 反推。目录名使用安全稳定编码，不直接拼接原始 ID 或可变聊天名称；附件引用必须经过验证。历史列表以 `sessions` 为准，并处理压缩后的展示消息。群聊策略生效批次与切换历史属于附录 F 的后续工作；本期不为其增加模拟状态。具体接入步骤见附录 B.1。
- 本页不提供从 Web 输入框续接 IM 会话，聊天归档／删除 UI 暂不加入；记录与工作空间文件的删除须分别定义。旧版 [prd.md §9](../../数字员工/docs/design/1023/prd.md#9-消息渠道设计与实现) 中去掉群聊策略的文字由附录 F 的后续决策覆盖，本期仍不实现群聊策略选择。

**自主任务（事件中心）段（1023 新增）**

- 本地演示页的动作列表操作栏保留数量和搜索，不显示「+ 配置专家动作」按钮；已有动作仍可通过行内入口查看或编辑。正式配置入口的位置由事件中心与专家任务页的职责划分决定，不从演示页缺少该按钮推断后端禁止创建动作。
- 展示事件中心中绑定当前专家的**「专家」执行动作**及其运行记录。截图所示，一个事件可有多个分支、每个分支可并行执行多个动作；同一事件还可同时执行工作流、工具或「智能体」动作。因此专家绑定应落在稳定的**执行动作 ID** 上，而不是整条事件根记录上。
- 事件中心负责事件接入、条件分支、动作顺序、发布版本和触发记录。专家任务 Tab 只展示／配置与当前专家相关的动作以及每次自主执行的结果；不复制一份事件源或处理流程。事件中心的「智能体」动作与「专家」动作是不同类型，不能全部算作本专家的任务。
- Timer 的「指定时间点／按间隔重复／Cron 表达式」及 WebHook、Pulsar、Kafka、MQTT 均由事件中心配置。专家任务 Tab 展示与该专家有关的动作和运行记录，可显示触发源类型，但不再提供另一套定时规则或 Hermes cron job 管理界面。
- 每次命中专家动作时创建**独立的一次执行记录和 Hermes session**，保存事件 ID、发布版本、分支 ID、动作 ID、专家 ID、输入快照、session ID、状态、结果与产物目录。不得续接人工对话或 IM session，也不创建 Hermes cron job。该次执行不写 `MEMORY.md`／`USER.md`。
- 新专家工作空间预建 `自主任务/`；建议产物按 `自主任务/<动作 ID>/runs/<执行 ID>/` 存放，该次 session 的 cwd 指向本次 runs 目录。Timer 与其它触发源沿用同一目录规则；多个分支／动作即使来自同一事件，也不共用一个 cwd。
- 旧 [prd.md §6 与 §6.10](../../数字员工/docs/design/1023/prd.md#6-独立定时任务历史方案已取消) 分别以 Hermes cron 和根级 `handler_type=expert`、`expert_id` 为前提，已被本次决定覆盖并在原文标为历史方案；专家删除时停用其动作并保留运行记录，复制专家不复制绑定。

#### 1.2.4 记忆 Tab

对应 [prd.md §7](../../数字员工/docs/design/1023/prd.md#7-记忆开关设计与实现)。

- 提供一个「启用记忆」总闸。打开时 `memory.memory_enabled` 和 `memory.user_profile_enabled` 都为 `true`；关闭时两项都为 `false`，一次保存写齐。新专家默认打开；复制专家继承开关，但记忆文件仍按 MVP 规则清空。
- 关闭后，新会话不注入两份记忆文件，也不提供内置 `memory` 工具。磁盘上的 `MEMORY.md`、`USER.md` 保留，内容仍可通过「专家画像」「用户画像」两个入口只读查看和切换；默认展示专家画像。重新开启后恢复新会话的记忆读写规则，已有内容不因切换而清空。开关选择在演示版刷新后保留；正式配置变更仅对新会话生效。
- 自主任务每次运行的记忆隔离不受总闸打开状态影响。Memory Provider 绑定、配置与解绑不在本期。

#### 1.2.5 技能 Tab

对应 [prd.md §8](../../数字员工/docs/design/1023/prd.md#8-技能获取渠道标签与主动学习开关)。沿用 MVP 的技能安装、启用／禁用和删除能力，本期增加获取渠道与主动学习规则；页面交互按当前原型：

- **获取来源**：每个技能有且只有一个来源，前台固定显示为「从平台导入」「本地上传」「对话习得」「复制专家」。列表、卡片来源标签和详情标题区须使用同一名称；进入专家时确定来源，后续编辑、更新和启停不改变。AI 主动或按用户明确指令创建的技能显示为「对话习得」，复制专家或专家模板带来的技能显示为「复制专家」；具体平台、文件名和模板版本只是补充信息，不增加第五类。
- Hermes 现有 `bundled`／`hub`／`agent` 不能直接等同于这四类来源。旧技能应按可核实的创建记录迁移；来源无法判定时先核实，不凭目录或使用次数猜测。
- **主动学习技能**：专家级开关，默认开启。关闭后，新会话的普通对话及后台复盘不再自主创建或完善技能；已有技能仍可加载，记忆复盘不受影响。用户明确要求创建或修改技能（包括 `/learn`）、从平台导入、本地上传和复制模板不受该开关限制。现有 `skills.write_approval` 仍独立负责写入审批；单个技能启停也不改变主动学习开关。保存后提示仅新会话生效。
- **列表与详情**：顶部显示已安装／已启用数量，提供名称搜索、启用状态和来源筛选，以及「从平台导入」「本地上传」。来源筛选默认「全部来源」，可选上述四类，不提供独立的「内置」筛选项。技能卡片展示名称、说明、来源及独立启停开关，不显示使用次数；卡片标签、详情与筛选结果使用相同来源名称。纯演示版将旧样例的 `source=内置` 显示并筛选为「从平台导入」，不据此推定正式服务端旧技能的真实来源。点击卡片任意非操作区域打开只读详情；启停和更多操作不打开详情。更多菜单只提供「卸载技能」，卸载前二次确认。详情显示来源、启用状态、可展开的技能包目录及文件内容；目录标题不加「示例」字样。演示版文件内容为本地模拟，正式实现须读取实际技能文件。
- **导入**：「从平台导入」弹窗按「我发布的／我添加的／内置」切换，可跨分类勾选、批量导入，已安装技能不再出现在候选项；候选名称字段只显示技能名称，内部 ID 用于勾选与去重，不附在名称后展示。导入后默认启用。「本地上传」原型接受 `.zip`、`.md`、`.json`、`.skill`，重名时阻止导入；正式实现须校验并安装实际包内容，不能只根据文件名生成技能记录。

#### 1.2.6 工具 Tab

沿用专家管理 MVP PRD 的可配置 Hermes 工具集，不与外部 MCP 服务混排。当前原型以卡片展示工具集名称、说明、工具数、就绪／缺密钥状态和独立启停开关；可按名称搜索、按启用状态筛选。点击卡片打开详情，查看工具列表并展开配置操作；保存配置或启停后提示新会话生效。原型中的示例工具描述、密钥状态与提供方选项须由实际工具集配置及服务端接口替换。

#### 1.2.7 MCP Tab

对应 [prd.md §15](../../数字员工/docs/design/1023/prd.md#15-mcp-优化导入--测通--填密钥)。

- MCP 配置归属当前 Agent/Profile，正式保存到其 `config.yaml` 的 `mcp_servers`；不同 Profile 的配置、凭据、启停和测试结果相互隔离。MCP 页随专家管理页当前专家上下文展示，不提供单独的「当前 Profile」切换入口。本版不提供 OAuth，也不展示会话加载或待刷新状态。HTTP/SSE 认证仅支持「无需认证」和 Bearer Token；stdio 不显示 HTTP 认证选项。粘贴到 OAuth 配置时明确提示本版不支持。
- 总览支持按服务名称搜索，顶部仅统计「已配置 X · 已启用 X」，数量不加单位，也不展示需处理总数；不提供「全部／需处理／已停用」状态筛选。每个服务可在卡片上独立启停；点击卡片打开详情，卡片更多菜单提供「编辑配置」「删除」。卡片展示名称、连接配置摘要（stdio 的启动程序与参数，HTTP/SSE 的服务地址）、工具数和连接状态；不重复显示开关对应的「配置已启用／已停用」说明，也不展示已启用工具数；详细测试结果留在详情。连接成功且发现工具、但所有工具均关闭时不标为连接故障；连接成功却没有工具、提示模板或资源时显示「未发现能力」。
- 总览提供「从平台导入」和「添加服务」。从平台导入沿用附录 E.8 的候选目录与批量选择规则；添加外部服务则在同一流程中选择「手动添加」或「粘贴配置」，**一次只新增一台**。编辑配置不显示创建方式 Tab：普通服务直接进入表单编辑，从平台导入的服务直接进入预填的 JSON 配置编辑。两种编辑方式均更新原服务，不新增副本；平台导入的身份在编辑后保留，候选目录仍排除该服务。手动添加填写服务名称及 Streamable HTTP、SSE 或本地命令 stdio 配置；HTTP/SSE 填地址和认证，stdio 填启动程序、参数、环境变量，并说明命令在 Hermes 后端机器运行。
- 粘贴配置支持单台服务的 `mcpServers`、`mcp_servers` 或名称映射格式。配置必须且只能包含非空 `url` 或 `command`；多台条目、格式错误及 OAuth 均阻止保存并给出明确原因。粘贴配置不提供独立的解析按钮；点击「测试连接」时先解析当前内容，解析成功后预览名称、连接方式、地址或命令、变量提醒和重名处理，格式错误则在测试区显示解析原因。本版外部服务重名时自动追加编号，不覆盖已有配置。修改粘贴内容后再次测试会重新解析。
- 手动新增、编辑及粘贴配置均提供保存前「测试连接」，测试**当前未保存内容**且不写配置。测试结果显示状态、时间和已发现工具列表；连接成功但没有工具时明确显示未发现工具，失败时显示原因且不展示旧工具。更改待测试配置后，旧测试结果不再作为当前结果展示。粘贴方式点击测试时先解析当前文本；格式错误仅显示解析错误。详情页测试已保存配置。正式测试必须连接、握手并发现 Tools、Prompts、Resources，不能用执行某个业务工具代替。现有按服务名测试的接口不足以测试未保存表单，正式实现需临时探测接口；原型测试仅使用演示数据，不发真实请求。
- 新建时「保存」创建停用服务；编辑时「保存」保留原启停状态；「保存并启用」保存并打开服务开关。未测试可保存并启用，详情显示「未测试」；**当前配置已测试失败或认证失败时不得直接保存并启用，也不得通过服务开关绕过失败状态**，但允许先保存以便后续修复。配置或测试输入改变后，旧测试结果不能充当当前配置已通过。正式 Bearer Token 保存在当前 Profile 的密钥作用域，`config.yaml` 仅保留变量引用，不向列表回传明文。
- 详情可测试已保存配置、查看连接配置与发现的工具，并进入编辑配置；连接测试模块只提供「测试连接」操作，显示上次测试状态及时间，不单独重复展示服务状态与发现工具数量。未测试时显示「未测试」，不展示虚构的测试时间。不在详情中启停服务、逐个启停工具或删除服务。Bearer Token 无效时在测试结果中显示原因，凭据修改统一通过「编辑配置」进入，不另设「更新密钥」按钮。仅当服务发现提示模板或资源时展示相应高级能力；Prompts 是可复用提示模板，Resources 是可读取内容，均不等同于执行操作的 Tools。通过卡片更多菜单删除配置时说明相关凭据可能需要单独清理。配置变更仅对新会话生效。

#### 1.2.8 消息渠道 Tab 与在线状态

对应 [prd.md §9](../../数字员工/docs/design/1023/prd.md#9-消息渠道设计与实现) 和 [§4](../../数字员工/docs/design/1023/prd.md#4-开启了消息渠道的专家启动策略)。产品只支持企业微信 AI Bot（`wecom`）、钉钉和飞书，不做 `wecom_callback`。

- 渠道页保留启停、凭据、Home 会话或群 ID、设置指南和保存／连接操作。渠道 ID 与 Secret 首次启用必填；已保存的 Secret 留空表示不修改，Home 为选填。企业微信填写 AI Bot 的 Bot ID／Secret；钉钉填写 Client ID／Client Secret，机器人 Code 与 Client ID 不同时可单独配置；飞书填写 App ID／App Secret。企微和飞书提供扫码配置，钉钉不提供。凭据由该专家的密钥作用域保存，读取配置时只返回是否已配置，不回传明文。
- 钉钉、飞书提供「群聊需 @」的「开启／关闭」选择，默认开启；企业微信不提供。提示用户该设置只控制群里有人 @ 专家时是否响应。
- 本期不提供「群聊会话策略」字段；默认按成员独立展示群聊记录，不模拟全群共享或策略切换。按当前 Profile 和渠道单独配置的策略属于附录 F 预备功能。
- 飞书固定使用**国内飞书**（domain=feishu）和 **WebSocket**（connection_mode=websocket）。页面不提供飞书／Lark 域名切换或 WebSocket／Webhook 连接方式切换，也不展示 Webhook 地址、Encrypt Key、Verification Token。Home 不作为连接必填项。
- 「群聊需 @」按专家和渠道分别保存，只控制群消息的触发条件，不影响私聊，也不与渠道启用开关联动；关闭渠道时保留原设置，重新启用后继续使用。
- 关闭开关时可「保存配置」而不连接；开启后点击「保存并连接」先检查渠道 ID 与 Secret，再应用连接。连接状态区分未配置、已关闭、待连接、已连接和连接失败；不能把“ID 已填写”当成真实连通。原型仅模拟连接状态，真实实现应取该专家 profile 的 gateway 运行状态及失败原因。访问授权／配对与传输连接是两件事，本卡片不新增允许用户字段。
- 每渠道增加默认关闭的「主动沟通」，以及「可私聊的人」「可发的群」两张名单。本期添加弹窗手填平台目标 ID，名称／备注选填；已有消息会话快捷带入待 session 保存真实平台目标 ID 后接入，原型不把 session ID 冒充发送 ID。名单展示名称、ID 摘要与上次测试结果，不把历史测试当实时可达状态。发送前仅在当前专家、当前渠道的名单内匹配，重名需选择，未匹配则停止。Home 不自动加入名单。企微普通目标的手填 ID 仅是匹配线索，必须在当次可发送会话中重新取得发送 ID；授权人例外但仍需进入名单。
- 每个名单目标提供「测试」弹窗，管理员可输入文字／Markdown、图片或文件并单次真实发送；钉钉原生图片需公网 URL，本地图片走文件附件。钉钉、飞书群文字可选 @ 指定成员；一次只发一种内容类型。文字测试在渠道已启用时可由管理员执行，不受「主动沟通」开关限制；图片／文件测试仍要求「允许收发文件」开启。弹窗展示平台已接受（不表示已读）、失败原因与阶段、结果未知及脱敏技术详情；名单只保留带时间的上次测试摘要。原型预置成功、固定失败和结果未知的目标 ID，按 ID 稳定复现，不展示额外场景选择器或「原型演示」文案，也不调用真实 CLI。
- 页面区分接收连接状态与机器人发送配置。启用渠道不等于 CLI 已授权、应用权限齐备或目标可达；「检查配置」只能核对已知凭据／权限，真实可达以实际测试或发送结果为准。测试失败不移除目标；请求结果未知不自动重发。
- 在群里 @ 别人，只限主动沟通已开启且在可发群名单中的群；企微不支持平台 @。文件和 @ 需分开发送时，按平台能力分成消息。
- 每渠道增加默认关闭的「允许收发文件」，覆盖图片、文件、语音、视频。当前 IM 对话的入站文件由适配器落地；发出的文件从该对话工作目录取。按名单主动发文件还要求主动沟通开启。
- 主动沟通和文件发送均使用**当前专家绑定的机器人身份**：企业微信 AI Bot、钉钉应用机器人、飞书应用 Bot。专家对话与事件中心自主任务统一调用产品受控发送入口，由入口校验渠道、开关、名单、媒体权限和目标，再调用对应 CLI；CLI 凭据与专家通用终端隔离，避免绕过开关。管理员测试仅对主动沟通开关作单次例外，仍须渠道已启用。接收 gateway 的在线状态和 CLI 出站能力分别判断；事件中心 Timer 由事件中心调度，**不因存在 Timer 就要求专家 IM gateway 常驻**。渠道完整重启、退避与失败态策略仍待拍板。

### 1.3 专家对话任务页

页面定位：与一个专家的某条人工对话 session 交互，右侧显示该专家未归档的对话任务列表。截图 3 是当前页面参考；当前流式回复、工具卡、HITL 和输入区的 MVP 行为仍沿用任务对话 MVP PRD。

顶部左侧的**返回按钮**返回专家列表；旁边可点击的专家头像与名称进入**当前专家管理页**，两者不是同一跳转。尚未选中已有任务或点击「新建任务」后，主区显示默认对话区：头像、名称、简介与首次发送提示；不显示「擅长领域」标题或其标签。

#### 1.3.1 工作目录与文件

- **工作目录**属于当前人工对话，默认等于专家工作空间根，可改为已有子目录。相对路径读写、终端和附件都以当前 cwd 为锚点；默认产物写在 cwd。本期不加阻止绝对路径写出 cwd 的硬沙箱，也不预设 `inputs/outputs/tmp`。消息渠道与事件中心自主执行分别使用其专属默认目录，不改变人工对话的根目录默认值。
- 对话页同时展示专家工作空间和当前工作目录；文件侧边栏从工作空间根展示整棵树，并标出当前 cwd。更改工作目录仅在空闲时允许，运行中禁用；切换影响后续相对路径和附件，不重建本会话已缓存的 `AGENTS.md` 或提示词。
- 用户 `@file` 的相对路径从当前 cwd 解析，但允许引用工作空间根内的文件；补全插入的路径必须按此规则可解析。旧 cwd 已在新工作空间根外时，允许范围回退为当前 cwd 并提示用户。
- 对话页工作空间树的根目录名为 `workspace`。根目录与子目录均可设为当前对话的工作目录；已是当前目录时重复设置不改变状态。该操作只改变当前对话的 cwd，不改变专家工作空间根路径。

#### 1.3.2 任务列表与归档

- 任务列表只列当前专家的未归档人工对话 session，排除 `source=cron`、消息渠道平台 source 与 `source=event_center`；不提供已归档切换或筛选。每项标明任务名称和所属工作目录，目录可单独打开工作空间。
- 点击「新建任务」只切到默认对话区，**不立即创建 session，也不出现新卡片**。用户首次发送文字或附件后才创建任务、加入列表并开始对话；默认任务名取首次发送内容去空白整理后的前 **20 个字符**，超出时末尾加省略号。之后可通过编辑图标改名。删除当前打开的任务并确认后，主区回到默认对话区，不留空白页面或失效的任务链接。
- 点击任务项或名称切换任务；**双击名称不打开编辑弹窗**。任务提供编辑名称、置顶／取消置顶、归档、删除操作；操作只在鼠标悬浮任务项时可用，点击操作不触发任务切换。改名通过编辑操作打开弹窗。
- 置顶任务排在普通任务前，并保留可识别的置顶状态；置顶或取消置顶后可继续执行其他任务操作。
- 归档当前正在看的任务后，右侧立刻移除它，主区切到下一条未归档任务或空态。从管理页归档任务弹窗打开任务时，主区可查看历史和继续发送，顶部仅提示「已归档」及恢复位置，不提供恢复按钮；右侧仍不显示它。恢复操作只在管理页「任务 → 平台对话 → 归档任务」弹窗中提供。
- 归档保留消息和工作目录文件；删除仍二次确认并硬删 session（[prd.md §12](../../数字员工/docs/design/1023/prd.md#12-任务归档)）。

#### 1.3.3 问题快速定位（1023 新增）

专家对话页提供「问题快速定位」，帮助用户按历史提问浏览当前任务的对话。

- **一个标记对应一次用户提问**，按对话时间顺序排列。锚点取本 session 中用户主动发送且实际展示的 `role=user` 消息；内部通知、审批选择、专家回复、思考、工具调用、状态提示和 HITL 卡片不单独产生标记。只有附件而没有正文的提问，用附件名称／「发送了文件」作标题。
- 标记位置对应提问在整段对话内容中的位置，而不是平均分布。点击标记将该问题滚动到对话区可视范围的顶部附近，并保留紧随其后的专家回答；高亮当前浏览位置所属的问题。切换任务时重新生成该 session 的标记，不沿用上一任务的定位。
- 悬停或键盘聚焦问题标记时，预览**用户问题**和该问题对应的第一段可见专家答复；不拿思考或工具日志充当回答。未回答时显示进行中／待回答状态，只有附件的问题以附件类型或名称标识。预览只读，不改变会话内容；点击定位后仍可正常滚轮、触控、键盘滚动。
- 新消息、流式回复、工具卡片展开／收起、窗口尺寸变化都会改变内容高度，标记位置须随实际布局更新。手动跳到历史问题时暂停自动滚到底部，并继续提供现有「回到最新」入口；跳到最新后恢复现有自动滚动规则。
- 对话没有用户问题时不显示导航轨；只有一个问题时显示一个标记。标记密集时须保证相邻问题仍可点选和预览；具体聚合样式见附录 C 待确认项。

这是一项**对话阅读与导航能力**，不需要改变 Hermes session、transcript、消息顺序或模型上下文。原生滚动能力仍保留，只替换可见的滚动导航表达。

验收：同一 session 的 N 次用户提问可定位到 N 个问题起点；悬停预览能区分问题与对应回答；点击历史标记后流式更新不强制拉回底部；切换任务后只展示新任务的标记；「回到最新」、滚轮和键盘滚动仍可用。

#### 1.3.4 对话体验与待细化项

岗位说明 Tab 配置的「预置问题」在本页输入区供用户一键填入，**不自动发送**；已有未发送草稿时，当前原型先确认再覆盖。它是专家预先维护的问题列表；[prd.md §11](../../数字员工/docs/design/1023/prd.md#11-快捷指令) 所说的用户可配置快捷指令仍是另一项待细化能力，不能与预置问题或 Hermes 的 `quick_commands` 斜杠 `exec`／`alias` 混为一项。

当前原型把同一轮连续的思考、工具调用和子智能体过程收进折叠轨：执行中展开，完成后收起，正式回复保持可见。待回应的审批优先展示；连续两条及以上澄清使用进度分页，只在未回答问题间切换并保留各题未提交草稿。澄清可选预设答案、填写其他答案或跳过；提交后在历史中展示结果。具体规则见 [prd.md §10.2](../../数字员工/docs/design/1023/prd.md#102-当前原型已明确的交互)。长回复扫读、排队与打断反馈等其余方向仍需补交互稿与验收条件。

## 2. 项目

### 2.1 项目列表页

页面定位：浏览和管理用户创建的项目，并进入项目详情页。正式接入时的项目模型、创建和删除边界沿用项目看板 MVP PRD。本工程的前端演示须覆盖以下操作：

- 项目列表可按名称和简介搜索；本页提供「新建项目」，不提供「新建专家」。每个项目展示名称、简介、状态、未归档看板任务的完成数／总数、成员和最近更新时间；点击项目进入详情。没有项目时提供创建入口，搜索无结果时可清空条件。
- 新建项目分为「项目信息」和「项目成员」两步。项目信息需填写名称与描述，并可从预设图标中选择或上传本地图片；成员步骤可按专家名称、简介或擅长领域搜索并勾选专家。提交后新项目及所选成员立即在列表和详情中可见。
- 项目可编辑名称、简介和图标；编辑不清空已有成员、目标、任务和文件。删除项目前须确认，确认后从列表移除项目及其演示数据。
- 列表操作的是**项目**及其看板任务，不把人工对话 session、消息渠道聊天或事件中心自主任务混入项目统计；项目任务的归档不复用对话归档语义。

### 2.2 项目详情页

页面定位：在同一项目内查看看板、动态、工作空间、目标记录和协作成员。正式任务状态机、允许执行的状态操作及服务端数据来源沿用项目看板 MVP PRD；**1023 当前没有另行拍板的项目详情页领域改版**。本工程的前端演示须覆盖以下功能路径：

- 项目详情展示基本信息及未归档任务的完成进度；可返回项目列表，并进入项目信息编辑和删除确认。
- 看板任务按**待办、进行中、暂停、已完成**四种业务状态查看。任务展示标题、当前状态、负责人、优先级和简要说明；已归档任务只在已完成分区按需显示，可从任务详情恢复。
- 新建任务需填写标题和项目成员负责人，可填写说明、优先级与前置任务。任务详情提供**任务详情、执行过程、评论**三个入口；可编辑、转交、更新状态、归档／恢复或删除任务。暂停时要求说明阻塞原因；完成时可填写结果。演示版在本地更新状态，正式接入时须遵守 MVP PRD 的状态与操作约束。
- 「发起目标」填写标题和描述，可选择本次拆解模型；提交后生成目标记录并模拟拆解。发起记录区分**待拆解、拆解中、已完成、拆解失败**，可查看目标描述、结果和关联任务，并可对待拆解或失败记录重新模拟拆解。目标记录与看板子任务有明确关联，重复拆解不得无故重复生成已有任务。
- 动态按时间查看项目内的任务协作和项目／成员事件，可按全部、任务协作、项目与成员筛选。任务的自动执行过程仍在任务详情中查看，不把它与项目级人工协作动态混为一类。
- 项目成员入口列出参与专家及其任务进度；可搜索并添加专家、为指定成员创建任务，移除成员前须确认。成员变更不自动删除既有任务。
- 项目工作空间独立于专家工作空间，可按目录浏览，支持新建文件夹、上传、预览、下载、重命名和删除文件或文件夹；删除前确认，文件夹删除须连同子项处理。工作空间文件可作为本地演示资料供查看。

需保持的边界：项目工作目录属于看板共享资源，**不是**专家工作空间；看板卡归档与人工对话 session 的 `archived` 是两套独立能力。自主任务不自动创建看板卡（[prd.md §5.8](../../数字员工/docs/design/1023/prd.md#58-和其它模块的边界)、[§12.1](../../数字员工/docs/design/1023/prd.md#121-和别的归档分清)）。

## 3. 专家模板

页面定位：浏览可复用的专家模板。模板页提供按名称、简介和标签搜索；不提供新建按钮。查看模板详情后可通过「使用模板」进入新建专家流程；创建行为仍沿用专家管理 MVP PRD。

这里的「专家模板」是独立产品入口。专家管理页岗位说明仅在从零创建且磁盘未填写时自动预填工作规范，不提供「使用模板」入口；这项默认句不构成专家模板页的新模板（[prd.md §3.5](../../数字员工/docs/design/1023/prd.md#35-自动预填与旧内容)）。

- `hermes_cli/config.py`、`cli.py`：现有 `quick_commands` 属于斜杠命令的 `exec`／`alias`，不是输入框提示词模板。
- `plugins/platforms/wecom/adapter.py`、`plugins/platforms/dingtalk/adapter.py`、`plugins/platforms/feishu/adapter.py`：接收入站消息后构造含平台、聊天类型、聊天 ID、用户 ID、可选线程 ID 的 `SessionSource`，再交给 gateway；各适配器本身不直接新建 SessionDB 任务。
- `gateway/session.py`、`gateway/run_turn.py`：`build_session_key` 用 profile、平台、聊天类型、聊天／线程／用户身份组成稳定路由键；群聊 `group_sessions_per_user` 默认为真，线程等共享路由有例外。 `SessionStore.get_or_create_session` 根据该键复用或创建 session，并在 SessionDB 写入平台 `source` 与来源元数据。普通后续消息会续接同一 session；成功 `/new`、`/reset` 产生新 session。页面按发起人切换要求真实路由可区分发起人，不能靠显示名拆分共享 route。
- `gateway/run.py`、`gateway/run_turn_runner.py`：gateway 每轮在所属 profile 的配置／凭据作用域内执行，并以 session ID 作为 agent `task_id`。当前 `_set_session_env` 没有传入专属 cwd，SessionStore 新建行也没有传入 cwd；仅靠创建 `消息渠道/` 目录**不会**让 IM 文件默认落到那里。
- `gateway/platforms/base.py`、各渠道媒体适配器：部分入站媒体会写到 profile 的 `cache/images|audio|documents` 等缓存目录，另一些适配器先保留下载 URL；目前没有统一保存到工作空间中消息任务目录的路径。产品要求「收到的文件落当前任务目录」时，需要在接纳消息并确定 session 后处理下载／归档与引用路径。
- `hermes_state_sessions.py`、`run_agent.py`：SessionDB 的 `source` 是字符串，支持明确保存 `cwd` 和 `profile_name`；一次性 agent 可以用独立 session ID 与自定义 `source` 落库，但 `AIAgent` 默认只为本地 CLI 自动写入启动 cwd，事件执行器须显式绑定并持久化本次 cwd。
- `js/expert-detail-page.js`、`js/chat-composer.js`、`js/store.js`：已修改原型的预置问题配置支持开关、增删、拖拽、最多 20 条及每条 200 字符；对话页点击后只填输入框。当前数据保存在原型的本地 store，并非 Hermes 的 `SOUL.md` 或已实现的服务端接口。
- `js/expert-tasks-page.js`、`css/app.css`：当前对话区是 `.chat-messages` 原生滚动容器，`onChatScroll` 判断是否离开底部，「回到最新」负责恢复自动滚动；`chatGroups` 已按 user 消息与 expert turn 分组。问题导航可在产品前端据 user 消息建锚点，不需要修改 Hermes transcript。

## 附录 B. 新增任务的 session 与目录方案

消息渠道的本期页面对象与数据规则以 §1.2.3 和下列 B.1 为准；群聊策略切换只记录在附录 F，不纳入本期演示。原型项目 [prd.md §16](../../数字员工/docs/design/1023/prd.md#16-消息渠道聊天与工作空间) 中不一致的目录规则须在正式接入前同步修订。自主任务执行器的细节仍待研发对齐。

### B.1 消息渠道聊天

1. 入站时记录 Profile、渠道、平台作用域、`chat_id`、`chat_type`、来源消息和发送者；群聊同时记录 Hermes `session_key` 以建立会话范围，单聊产品范围字段为 `null`，会话段直接归入聊天。产品按 Profile＋渠道＋平台作用域＋`chat_id` 维护**一条聊天聚合记录**，不以单条 `session_id` 建卡。无可信聊天 ID 的事件不能编造聚合键。最近处理时间只随 Hermes 真正处理的入站消息更新。
2. 本期群聊按成员范围展示记录，不配置或模拟策略切换。成员范围使用真实 `session_key`，会话段使用真实 `session_id`；当前 `gateway_routing` 只给出目前路由目标，历史以 `sessions` 为主，并记录 `/resume` 造成的路由重绑。策略生效时间与切换前后关系推迟到附录 F 实现。
3. 在调用 agent 前将当前段 cwd 写入 SessionDB 并绑定该轮工具 cwd。群聊持久映射聊天、`session_key` 范围和 `session_id` 段到各自目录；单聊只映射聊天和 `session_id` 段。目录名用安全稳定编码，不直接拼原始 ID 或可变名称。聊天目录入口停在 chat 层，存在范围时可打开范围目录，段可打开对应目录。旧数据先建立映射、保留已有文件，不静默覆盖。
4. 对消息保存结构化发送者和已证实的 `/new`、`/reset` 指令事件。按消息行 `id` 输出会话记录，区分普通消息、内部通知、工具调用和附件；压缩 continuation 不生成新可见段。入站附件在临时缓存清理前归档到当前段，建立消息／附件 ID 到实际文件的验证索引，幂等处理重试、重名、非法文件名与失败。
5. 正式列表聚合、搜索、筛选和统计在服务端执行；运行中须依据 Hermes turn 执行状态，不复用只表示近期活跃的 `is_active`。状态不可确认时返回未知而不是 0。现有 `GET /api/sessions` 和 `GET /api/sessions/{id}/messages` 可复用部分读取能力，尚需按聊天聚合的接口及压缩历史读取规则。

### B.2 自主任务（事件中心）

1. 事件中心先保存事件接入与发布版本；一条事件进入分支后，只有命中的**专家类型执行动作**会创建本专家任务。动作记录保存稳定 `action_id`、`expert_id`、指令模板及必要的投递配置；其他动作仍由事件中心执行。
2. 每次命中动作，事件中心先用「事件投递 ID + 发布版本 + 动作 ID」等稳定键去重，生成唯一 `execution_id` 并记录输入快照，再创建 `自主任务/<action_id>/runs/<execution_id>/`。Timer 与其它触发源使用同一规则；重复投递或重试应回到同一逻辑执行记录，不能无故生成第二条任务。
3. 专家执行器在对应 profile 的配置、密钥与终端策略作用域中，以**独立 session ID**运行一次 agent；在 SessionDB 写 `source=event_center`、`profile_name`、本次 `cwd`，并在事件中心执行记录中保存这个 session ID。事件 payload 作为本次用户输入按模板渲染，不写进 `SOUL.md` 或固定系统提示词。
4. 执行结束后，分别记录 agent 结果、文件产物及 IM 投递结果。运行记录始终归属事件中心动作；专家任务 Tab 按 `expert_id` 查询动作和执行，不靠 SessionDB `source` 猜动作关系。`session_id` 用于打开只读 transcript，失败重试、人工干预及能否续聊需另定规则。

此方案借用 Hermes 已有的 SessionDB、profile 作用域和一次性 agent 运行能力；事件中心 Timer 与其它触发源共用动作执行链，不往 Hermes cron 建 job，也不让不同事件触发共享一个会话的提示词缓存。[prd.md §6 与 §6.10](../../数字员工/docs/design/1023/prd.md#6-独立定时任务历史方案已取消) 已标为历史方案，后续详细规格按本节的动作级绑定展开。

## 附录 D. 实现方案概要（源码与厂商 CLI 核对）

以下是可落地的技术路径，供设计和研发拆分；厂商 CLI 命令以接入时所安装版本的 `--help`／Schema 再核对。2026-10-09 本机版本为 `wecom-cli 1.3.4`、`dws v1.0.63`、`lark-cli 1.0.97`；已只读核对版本、官方命令文档及 DWS 发送 Schema，**未向任何真实会话发送测试消息**。安装与命令契约可用，不等于当前专家已具备授权、应用权限或目标可达性。

### D.1 Hermes 可复用能力

- **专家资料与配置**：一个专家对应一个 Hermes Profile；岗位说明复用 `SOUL.md` 的 `GET/PUT /api/profiles/{name}/soul`。预置问题、名单及页面开关由产品按专家存储，不写入 `SOUL.md`。
- **人工对话与文件**：复用 `session.create(cwd=工作空间根)`、`session.cwd.set`、SessionDB 和 `terminal.cwd`。`@file` 的 `allowed_root` 扩到专家工作空间根；批量删除在产品文件接口校验真实路径与符号链接，不新增模型工具。
- **消息渠道聊天与历史段**：复用 Hermes 的 `SessionSource`、`build_session_key`、`SessionStore.get_or_create_session` 和 SessionDB 消息。产品维护 `chat_id` 聊天聚合、群聊 `session_key` 范围、用户可见重置段及内部 session 谱系；群聊段 cwd 位于聊天／范围／段三级目录，单聊段 cwd 位于聊天／段两级目录。段目录同时写入 SessionDB、轮次上下文和对应 `task_id` 的工具 cwd。入站媒体从 Hermes 缓存／下载源持久复制到该段 `收到文件/` 后交给 agent，并建立按消息检索的文件索引；卡片目录停在聊天根。
- **自主任务**：事件中心负责 Timer 等触发、版本、分支、动作和去重；执行器在目标 Profile 的配置／凭据作用域中复用 Hermes `AIAgent` + SessionDB，每次动作独立创建 `source=event_center` 的 session、绑定 `自主任务/<动作 ID>/runs/<执行 ID>/` 为 cwd，并把 session ID 回写事件中心运行记录。产品不调用 Hermes cron 创建 job；记忆隔离同时关闭 memory 工具集，不能只设置 `skip_memory=True`。
- **归档、记忆、MCP**：人工对话归档复用 `sessions.archived`；记忆总闸写 `memory_enabled`、`user_profile_enabled`；MCP 复用现有服务列表与真探针，导入须逐台合并，不能调用整表替换接口。
- **技能获取渠道与主动学习**：渠道作为当前专家的产品元数据记录，不从 Hermes `bundled`／`hub`／`agent` 猜测。主动习得关闭时须同时约束前台引导和后台技能复盘，不能仅把 `skills.creation_nudge_interval` 设为 0，也不能关闭包含记忆的整个后台复盘；明确的用户学习指令仍按写入审批规则执行。
- **对话页轻交互**：预置问题作为专家级产品配置由对话页读取，点击后只更新输入缓冲；问题快速定位从已展示的用户消息与其首段可见答复建立前端锚点，复用现有滚动容器和「回到最新」，无需改 Hermes transcript。

### D.2 三家渠道的主动沟通与文件

当前会话回复优先沿用 Hermes gateway 适配器：企微和飞书适配器已有本地文件上传发送路径，钉钉 session webhook 适配器仅支持文本／Markdown，本地文件使用钉钉机器人 CLI。**名单内主动发送与管理员测试统一走产品受控出站入口**，由入口持有按专家隔离的 CLI 调用资格并核对渠道、开关、名单、内容类型和路径，再以机器人身份调用 CLI。专家不能从通用终端读取完整凭据绕过该入口；仅用 UI 开关或提示词无法强制限制。管理员测试只对主动沟通开关豁免一次，仍要求渠道已启用，媒体仍要求收发文件开关开启。

「CLI 授权」在本节只指**调用资格**：安装机器上的登录态、应用凭据、API 权限或目标会话可达范围；它与最终消息显示的**发送者身份**分开。企微 `message aibot send`、钉钉 `send-by-bot`、飞书 `--as bot` 都以机器人名义发消息和文件。

- **企业微信 AI Bot**：每专家用独立 `WECOM_CLI_CONFIG_DIR` 保存 CLI 机器人授权，通过 `wecom-cli auth init` 绑定后用 `auth show` 核对状态及 Bot ID，须与渠道 Bot ID 一致；不能假定填入 Hermes Bot ID／Secret 后 CLI 自动可用。根据 [WecomTeam 消息 CLI](https://github.com/WecomTeam/wecom-cli/blob/main/skills/wecomcli-message/SKILL.md)，授权人用 `wecom-cli identity whoami`，其他目标先用 `wecom-cli message aibot sessions list` 获取**本次**可发送会话，再调用以智能机器人身份发送的 `wecom-cli message aibot send --json ...`。手填 ID 仅供匹配，普通目标必须从当次列表复制发送 ID；授权人也须在产品名单中。列表数量以实际回包为准。本地媒体先用 [媒体 CLI](https://github.com/WecomTeam/wecom-cli/blob/main/skills/wecomcli-media/SKILL.md) 的 `wecom-cli media upload --json '{"file_path":"..."}'` 取得 `media_id`，再发送图片／文件；原生语音需 AMR，语音和视频暂不进通用测试弹窗。Hermes 现有企微适配器的群聊主动发送受被动回复 `req_id` 限制，不能等同于此 CLI 的群聊主动发送能力。[CLI 配置与返回格式](https://github.com/WecomTeam/wecom-cli/blob/main/docs/cli-reference.md)另见官方参考。
- **钉钉机器人**：将当前专家映射到正确的 DWS 组织／账号 profile，调用时显式传 `--profile` 及渠道 Robot Code；群可用 `dws chat +chat-bots --group <openConversationId> --format json` 辅助核对机器人。本机 `dws v1.0.63` 的 `dws chat +messages-send --as bot --robot-code ...` 可发群／单聊文本、Markdown 和 @；当前 `--help`／Schema 还支持机器人**单目标** `--file`（`--file-path` 为兼容别名）上传文件，以及 `--image-url` 发送公网图片。文件须位于 CLI 工作目录允许的相对路径内；本地图片按文件附件发送。群聊用 `--group <openConversationId>`，单聊用 `--users <userId>`，二者互斥；群文字 @ 用 `--at-user-ids`。多群 `--groups` 只用于支持的类型，不能套用单目标文件能力。[DWS 机器人原子命令](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli/blob/main/skills/multi/dingtalk-chat/references/chat/chat-bot.md) `dws chat message send-by-bot` 仅作 Shortcut 缺字段时的底层入口。官方页面仍有 Shortcut 不支持 Bot 富媒体的旧描述，以部署版本的 Schema 与真机验证为准。
- **飞书机器人**：CLI 绑定当前专家现有 App ID／Secret，显式选对应 profile 与 `--as bot`，核对 `im:message:send_as_bot` 权限；不切换真人身份。根据 [larksuite 消息 CLI](https://github.com/larksuite/cli/blob/main/skills/lark-im/references/lark-im-messages-send.md)，用 `lark-cli im +messages-send --as bot --chat-id oc_... --text/--markdown` 发群，或 `--user-id ou_...` 发单聊；`--image`、`--file` 自动上传工作目录内的相对文件。原生 `--video` 需封面、`--audio` 需 Opus，暂不放入通用测试弹窗。群 @ 可先用 `im +chat-members-list --as bot` 核对成员，再在文本／富文本中使用 `<at user_id="ou_...">...</at>`。Bot 可搜索和列出可见群，但[不能列出单聊会话](https://github.com/larksuite/cli/blob/main/skills/lark-im/references/lark-im-chat-list.md)；人员 ID 由管理员手填或已有入站会话带入。Bot 发送还受应用权限、可用范围、群成员身份和单聊关系约束。

产品解析 CLI 返回时统一记录 `accepted / failed / unknown`、上传或发送阶段、平台错误码、任务／消息标识（若有）、来源 session 与时间。企微 CLI 返回结构化 JSON 或透传平台错误，不能假设有消息 ID；钉钉须检查任务／逐目标结果，个人身份的 `query-send-status` 不直接套用于 Bot；飞书 JSON 成功含 `message_id`，错误含 code/message。平台接受不等于已读；进程超时或响应无法判断时保留「结果未知」，不自动重发。管理员浏览器上传的测试文件暂存到当前专家的安全测试目录；正式专家发送只读取来源 session 工作目录，完成后清理临时测试文件。

**收文件**与主动发送分开：当前 IM 对话的附件首先由 Hermes 适配器接收／缓存，产品将可用文件归档到该消息 session 的 cwd。历史资源补拉可按需使用飞书 [`+messages-resources-download --as bot`](https://github.com/larksuite/cli/blob/main/skills/lark-im/references/lark-im-messages-resources-download.md)、钉钉 `dws chat +messages-resource-download` 或企微 `wecom-cli media download`，但必须以真实消息 ID／资源 ID 和各 CLI 可访问的身份为前提；历史补拉不是实时收文件的前置步骤。原生语音／视频格式受平台限制，不能把“能发送文件附件”表述成所有平台都支持原生语音或视频消息。

## 附录 F. 预备功能：群聊会话策略（本期不实现）

**状态：仅记录后续需求。** 本期不在渠道配置页增加策略字段，也不在消息渠道对话记录弹窗展示策略、全群共享范围或策略切换历史；演示数据只覆盖成员独立的群聊记录。以下规则在后续排期、后端设计和验收时生效，不作为本期原型验收项。

### F.1 配置范围与用户语义

- 每个渠道的「启用渠道」配置区提供单选字段 **群聊会话策略**，按**当前 Profile × 当前渠道**分别保存。例如质量分析专家的飞书选择不影响该专家的钉钉，也不影响其他专家。未连接时可以预选；关闭渠道后保留已保存的选择。
- **成员独立（默认）**：同一普通群聊中，每位获准与专家交互的成员拥有独立上下文。**全群共享**：同一普通群聊中，获准交互的成员共用上下文；任一有权执行 `/new` 的成员发出该指令，会为整份共享上下文开启新会话。共享模式须提示成员之间会看到共同上下文，且 `/new` 的作用范围扩大到全群。
- 字段说明为「仅影响后续进入 Hermes 的普通群聊消息；不会合并已有会话。单聊不受影响。」消息能否进入 Hermes 仍受渠道连接、授权及 @ 唤醒规则约束；策略不修改企业微信、钉钉、飞书后台权限，也不使原本被拒绝的消息进入会话。
- 有真实 `thread_id` 的渠道线程仍按**每个线程独立、线程内成员默认共享**的既有路由处理；本字段只控制**没有线程 ID 的普通群聊**。单聊不受此字段影响。

### F.2 后端解析与兼容

- 现有 Hermes `group_sessions_per_user` 是网关级布尔配置，默认 `true`。不能只写渠道适配器的 `platforms.*.extra`：适配器和 SessionStore 可能分别使用不同配置生成 `session_key`。后端须提供唯一策略解析入口，供适配器消息守卫、排队逻辑和 SessionStore 共用同一结果。
- 兼容优先级为：**当前 Profile 的当前渠道设置 → 已有网关级设置 → 默认「成员独立」**。升级时若旧配置显式把全局值设为 `false`，新页面和实际运行不得悄悄改回默认值；须正确展示继承的有效选择及来源。没有渠道级覆盖时继续遵循旧全局配置。
- 产品需分别保存**已保存的选择**、**当前实际生效的选择**及生效批次；两者不一致时不能把保存成功解释为运行时已经切换。

### F.3 保存、生效与切换

- 已连接的渠道修改后先显示「已保存，待消息网关重启后生效」，提供明确的「保存并重启」操作；等待运行中的请求完成后切换。未连接的渠道在下次连接时生效。页面须区分已保存、待生效、重启失败与实际生效四种状态。
- 切换生效前已开始处理的消息按旧策略完成，后续消息按新策略路由，不把一次处理拆到两个上下文。**成员独立 → 全群共享**：保留成员历史，后续普通群消息进入共享 `session_key` 并从新 `session_id` 开始。**全群共享 → 成员独立**：保留共享历史，后续各成员进入自己的范围并开启新会话。
- **切回曾用策略时仍须开启新会话**，不能因确定性 `session_key` 与旧值相同而续接切换前的 `session_id`。后端记录策略生效批次或显式结束旧路由；记录页据此把新策略对应范围标为「当前」，旧范围和旧段作为历史保留。策略切换不删除聊天记录或工作空间目录，同一聊天位置仍只形成一张聚合卡。
- 共享会话的逐消息发送者、原始 `/new` 指令及策略切换事件须结构化保存；不能从共享 session 的单一 `user_id` 或消息正文前缀推断所有发送者，也不能只根据当前 `gateway_routing` 反推历史。共享成员的目录、附件与消息仍按已验证的引用定位。

### F.4 后续验收

- 企业微信、钉钉、飞书的配置分别保存；未连接时可设置、关闭后保留，单聊及带真实 `thread_id` 的线程行为不变。旧的显式全局 `false` 按兼容优先级正确展示与生效。
- 两名成员在成员独立模式使用不同 `session_key`，在全群共享模式使用相同 key；未获授权或未满足 @ 规则的消息仍被拒绝。
- 切换前后的会话在记录页同时可见，只有实际生效策略对应的新范围标「当前」；切回旧策略不会恢复旧上下文。保存、待生效、重启失败、实际生效与共享模式 `/new` 的影响范围均可验证。
