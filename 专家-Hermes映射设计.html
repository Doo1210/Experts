专家功能项与 Hermes 映射设计

基于 专家.md 的功能草案，整理“可直接映射的 Hermes 能力”和“需要新增封装的能力”，用于前后端接口对齐与实施拆分。

核心结论

“专家”建议映射为 profile + soul.md + skills + tools/MCP； “任务”建议映射为 session + run_conversation()（复杂协同可升级到 kanban task）。

1. 专家卡片页映射

设计功能项 Hermes 对应能力 映射说明
卡片展示：名称、头像、介绍、擅长领域 profile + 自定义元数据文件 建议每个专家一个 profile，展示字段存 expert.yaml（新增）
更多：编辑、删除 profile 管理能力 编辑改 expert.yaml/soul.md，删除删 profile 目录
发起任务 AIAgent.run_conversation() 进入专家任务页后，按专家 profile 运行会话
管理 profile 配置 + tools + skills + memory 进入专家详情页，映射到配置读取接口

2. 新建/编辑专家映射

弹窗字段 建议存储 Hermes 映射点
名称、介绍、头像、擅长领域 expert.yaml（新增） UI 元信息，不建议直接写入核心 config
人设：核心职责/工作流程/行为准则 soul.md 由系统提示词加载链注入 agent persona
能力：技能 ~/.hermes/<profile>/skills/ 安装/启用技能并作为可调用能力
能力：MCP 工具 config.yaml 的 tools/MCP 配置 按平台和工具集启用，决定可用工具表

3. 专家任务页映射

设计功能项 Hermes 对应 实现建议
对话日志区 session transcript 读取会话消息列表，映射 user/expert 对话
执行日志（思考/技能/工具/回复） agent callbacks 汇聚 step/tool/stream 回调，前端实时展示任务轨迹
新建任务 新 session 或新 task 简单模式：新 session；高级模式：kanban task
任务列表（名称/时间/产物） session list + title 会话标题作为任务名，创建时间取 session 创建时间
任务产物 workspace 文件 约定 outputs 目录并按任务聚合展示

4. 专家管理页映射

管理项 Hermes 映射 状态
人设 soul.md + profile config 可直接映射
工作空间（资料/产物） profile 工作目录（inputs/outputs 约定） 需定义目录规范
任务（运行中/历史） session 存储 + 运行态注册表 可直接映射
记忆 memory provider 配置与状态 可直接映射
技能 skills 目录与安装状态 可直接映射
工具（Tools/MCP） toolsets + MCP server 配置 可直接映射
IM 渠道 gateway 平台配置 可直接映射
权限管控 toolset 开关 + approval + delegation 限制 需二次封装为业务权限模型

5. 前端类型字段映射建议

Expert

profile -> profile_name
displayName -> expert.yaml.display_name
intro -> expert.yaml.intro
avatarUrl -> expert.yaml.avatar_url
domains[] -> expert.yaml.domains[]
coreDutyMd/workflowMd/behaviorMd -> soul.md 分节
skills[] -> skills 安装列表
tools[] -> 启用工具集 + MCP 列表

ExpertTask

id -> session_id (或 kanban task id)
title -> session title
status -> pending/running/completed（由运行态 + 会话结束态推导）
createdAt -> session.created_at

ChatMessage / TaskProgressStep

ChatMessage.role -> user/assistant 映射 user/expert
ChatMessage.content -> transcript content
TaskProgressStep(type=thought/skill/tool/reply) -> 回调事件统一流

6. 推荐 API（最小可用版）

接口 用途 备注
GET /experts 列表专家卡片 聚合 profiles + expert.yaml
POST /experts 创建专家 创建 profile + 写 expert.yaml + soul.md
PATCH /experts/:profile 编辑专家 更新基础信息与 persona
DELETE /experts/:profile 删除专家 需先终止运行中的任务
GET /experts/:profile/tasks 任务列表 按 session 聚合
POST /experts/:profile/tasks 新建任务 启动首条 run_conversation
POST /tasks/:id/messages 继续任务对话 同 session 追加一轮
GET /tasks/:id/events 实时执行日志 SSE/WS 推送 progress

7. 落地注意事项

  • 默认“编辑专家配置”在下次会话生效，避免中途改 system prompt 破坏缓存。
  • 非密钥配置（专家介绍、人设、阈值）放配置文件，不放环境变量。
  • 任务日志优先走结构化回调事件，不直接依赖原始日志文件。
  • 多专家并行建议一专家一 profile，保证隔离（会话、记忆、工具配置）。
  • 复杂项目协同可升级为 kanban board + 专家 worker 指派。
